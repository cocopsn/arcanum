### Solución
```javascript
function faltantes_interfaz(objeto, interfaz) {
  const props = new Map(objeto.propiedades.map((p) => [p.nombre, p.tipo]));
  const out = [];
  for (const ip of interfaz.propiedades) {
    if (!props.has(ip.nombre)) out.push(`falta:${ip.nombre}`);
    else if (props.get(ip.nombre) !== ip.tipo) out.push(`tipo:${ip.nombre}`);
  }
  return out.sort();
}
```
```python
def faltantes_interfaz(objeto, interfaz):
    props = {p["nombre"]: p["tipo"] for p in objeto["propiedades"]}
    out = []
    for ip in interfaz["propiedades"]:
        if ip["nombre"] not in props:
            out.append("falta:" + ip["nombre"])
        elif props[ip["nombre"]] != ip["tipo"]:
            out.append("tipo:" + ip["nombre"])
    return sorted(out)
```
### Pistas
- Indexa las propiedades del objeto por nombre y recorre las de la interfaz.
- Una propiedad con el nombre correcto y otro tipo tampoco cumple.

## ¿Qué entra a la interfaz?
type: multiple_choice
id: que-entra
tiempo: 2

Para la interfaz `ActivoOperativo` (equipos médicos y vehículos), ¿cuál de estas propiedades pasa la prueba del significado compartido?

### Opciones
- [x] `estado_operativo`, con la lista común disponible, en_uso, en_mantenimiento y fuera_de_servicio.
- `uso`, que en equipos son horas de encendido y en vehículos kilómetros.
- `placa`, porque algún día podría haber equipos con placa.
- `clase_riesgo`, porque es importante para la seguridad.
### Justificación
`estado_operativo` responde la misma pregunta con el mismo dominio de valores en ambos tipos, y el tablero de disponibilidad la consume para todos. `uso` mezcla unidades; `placa` sólo existe en vehículos; `clase_riesgo` es importante pero sólo significa algo para equipos médicos. Importancia no es significado compartido.

## Un tercer tipo de activo
type: production
id: tercer-tipo
tiempo: 10

La red agrega **camillas motorizadas**: tienen nombre, estado operativo, batería (porcentaje), ciclos de carga y una revisión cada 500 ciclos. No tienen placa ni horas de uso. Explica si implementan `ActivoOperativo`, qué propiedades quedan en el tipo, si su mantenimiento es una acción propia o compartida, y qué harías si la camilla no tuviera fecha de próximo mantenimiento.

### Modelo
- **Implementa la interfaz:** sí, porque tiene nombre, estado operativo con la lista común y una fecha de próxima revisión que se calcula desde los ciclos.
- **Propiedades propias:** `bateria_pct` (entero) y `ciclos_carga` (entero); ninguna entra a la interfaz, porque no comparten significado con los otros tipos.
- **Mantenimiento:** acción propia `ProgramarRevisionCamilla`, con precondición «respeta el intervalo de 500 ciclos», porque la regla es distinta.
- **Sin fecha de próximo mantenimiento:** no se rellena con un valor falso para cumplir; se calcula y se publica (si la regla lo permite) o la propiedad de interfaz se declara opcional y el tablero muestra «sin fecha programada».
### Regla
Un tipo nuevo implementa una interfaz sólo si cumple su significado sin rellenos; lo específico se queda en el tipo y las reglas distintas se escriben como acciones distintas. Nunca se inventa un valor para cumplir un contrato.
### Rúbrica
- Decide con la prueba del significado compartido si la camilla implementa la interfaz.
- Mantiene batería y ciclos en el tipo.
- Escribe una acción de revisión propia con su precondición.
- Rechaza rellenar la fecha con un valor falso y propone una alternativa honesta.
