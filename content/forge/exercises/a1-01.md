# A1-01 · Complejidad, invariantes y cotas

Banco ligero de la ruta A1. Entrena la misión de la celda: probar correctitud y costo de búsqueda binaria e insertion sort, y
defender por qué un invariante alcanza. La teoría está en ITC C1; aquí se practica la prueba.

## Antes de leer: ¿cuántas vueltas da la búsqueda binaria?
type: prediccion
id: a1-01-pred-vueltas
rol: prediccion

Una búsqueda binaria sobre un arreglo ordenado de 1,000,000 de enteros reduce el intervalo a la mitad en cada vuelta. Sin
calcular con detalle, ¿cuántas vueltas da como máximo antes de terminar?

### Opciones
- Alrededor de 1,000
- [x] Alrededor de 20
- Alrededor de 500,000
- Depende de dónde esté el valor: hasta 1,000,000

### Justificación
Tras k vueltas queda un intervalo de tamaño a lo sumo n / 2^k. Con n = 10^6, 2^20 ≈ 1.05 × 10^6, así que en unas 20 vueltas
el intervalo se vacía. La posición del valor cambia cuándo se encuentra, pero no puede hacer que el lazo pase de
⌊log₂ n⌋ + 1 vueltas. 1,000 es √n, que no sale de ningún argumento de mitades.

## Búsqueda binaria desvanecida: la frontera
type: desvanecido
id: a1-01-desv-frontera
lang: javascript

Completa `primerMayorIgual(a, x)`: devuelve el primer índice i con a[i] >= x en un arreglo ordenado, o a.length si no existe.
En cada nivel se ocultan más pasos.

### Pasos
1. Abre el intervalo semiabierto [lo, hi) = [0, n): la respuesta puede ser n si todo es menor que x.
2. Elige un mid dentro de [lo, hi) que nunca valga hi.
3. Si a[mid] < x, mid y todo lo anterior quedan descartados; si no, mid es candidato y hi baja a mid.
4. Al salir, lo === hi y ese índice es la respuesta.
5. Enuncia el invariante que hace correcta la salida.

### Plantilla
```javascript
function primerMayorIgual(a, x) {
  // <paso 1>
  let lo = 0;
  let hi = a.length;
  // </paso 1>
  while (lo < hi) {
    // <paso 2>
    const mid = lo + Math.floor((hi - lo) / 2);
    // </paso 2>
    // <paso 3>
    if (a[mid] < x) lo = mid + 1;
    else hi = mid;
    // </paso 3>
  }
  // <paso 4>
  return lo;
  // </paso 4>
}
```

### Casos
```json
[
  { "input": [[], 5], "expected": 0 },
  { "input": [[1, 3, 5], 0], "expected": 0 },
  { "input": [[1, 3, 5], 3], "expected": 1 },
  { "input": [[1, 3, 5], 4], "expected": 2 },
  { "input": [[1, 3, 5], 9], "expected": 3 },
  { "input": [[2, 2, 2], 2], "expected": 0 },
  { "input": [[1, 2, 2, 2, 3], 2], "expected": 1 }
]
```

### Niveles
- 1: 3
- 2: 3, 5
- 3: 1, 3, 4, 5

### Rúbrica
- El invariante habla de los dos lados: todo índice menor que lo cumple a[i] < x y todo índice desde hi cumple a[i] >= x.
- Explica por qué se cumple al inicio (no hay índices fuera de [0, n)).
- Explica por qué, al salir con lo === hi, el invariante deja a lo como la primera posición con a[i] >= x.

## La versión que encuentra «alguna» aparición
type: contraejemplo
id: a1-01-contra-primera

Un compañero dice que su búsqueda devuelve la **primera** aparición de x porque «si x está, siempre está en [lo, hi]». Da
una entrada válida (arreglo ordenado de enteros, a lo sumo 50 elementos) donde su función y la de referencia difieran.

### Firma
```javascript
function primeraAparicion(a, x) {
  // devuelve el primer índice con a[i] === x, o -1
}
```

### Precondición
```javascript
function pre(a, x) {
  if (!Array.isArray(a) || a.length > 50 || !Number.isInteger(x)) return false;
  for (let i = 0; i < a.length; i++) {
    if (!Number.isInteger(a[i])) return false;
    if (i > 0 && a[i - 1] > a[i]) return false;
  }
  return true;
}
```

### Casi correcta
```javascript
function primeraAparicion(a, x) {
  let lo = 0, hi = a.length - 1;
  while (lo <= hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (a[mid] === x) return mid;
    if (a[mid] < x) lo = mid + 1;
    else hi = mid - 1;
  }
  return -1;
}
```

### Referencia
```javascript
function primeraAparicion(a, x) {
  let lo = 0, hi = a.length;
  while (lo < hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (a[mid] < x) lo = mid + 1;
    else hi = mid;
  }
  return lo < a.length && a[lo] === x ? lo : -1;
}
```

```json
[[1, 2, 2, 2, 3], 2]
```

## Insertion sort que cuenta su trabajo
type: code
id: a1-01-code-inversiones
tiempo: 12

Implementa insertion sort y devuelve `[ordenado, desplazamientos]`, donde desplazamientos es cuántas veces moviste un
elemento una posición a la derecha. No uses `sort`. Ese número debe coincidir con las inversiones de la entrada: es la cota

### Especificación
Para i de 1 a n-1: guarda v = a[i]; mientras j >= 0 y a[j] > v, mueve a[j] a j+1 y cuenta 1; coloca v en j+1. Compara con
`>` estricto para que la ordenación sea estable.

### Firma
```javascript
function ordenarContando(a) {
  // tu código
}
```
```python
def ordenar_contando(a):
    # tu código
    pass
```

### Casos
```json
[
  { "input": [[]], "expected": [[], 0] },
  { "input": [[7]], "expected": [[7], 0] },
  { "input": [[1, 2, 3]], "expected": [[1, 2, 3], 0] },
  { "input": [[3, 2, 1]], "expected": [[1, 2, 3], 3] },
  { "input": [[2, 1, 2, 1]], "expected": [[1, 1, 2, 2], 3] },
  { "input": [[5, 4, 3, 2, 1]], "expected": [[1, 2, 3, 4, 5], 10] },
  { "input": [[4, 1, 3, 9, 7]], "expected": [[1, 3, 4, 7, 9], 3] }
]
```

### Solución
```javascript
function ordenarContando(a) {
  const b = a.slice();
  let movs = 0;
  for (let i = 1; i < b.length; i++) {
    const v = b[i];
    let j = i - 1;
    while (j >= 0 && b[j] > v) {
      b[j + 1] = b[j];
      j--;
      movs++;
    }
    b[j + 1] = v;
  }
  return [b, movs];
}
```
```python
def ordenar_contando(a):
    b = list(a)
    movs = 0
    for i in range(1, len(b)):
        v = b[i]
        j = i - 1
        while j >= 0 and b[j] > v:
            b[j + 1] = b[j]
            j -= 1
            movs += 1
        b[j + 1] = v
    return [b, movs]
```

### Pistas
- Copia la entrada: los casos comparan contra el arreglo original intacto.
- Cada iteración del while corrige exactamente una inversión; por eso el contador coincide con ellas.

## ¿Qué invariante alcanza para insertion sort?
type: multiple_choice
id: a1-01-mc-invariante
rol: recuperacion

Sin volver al libro: al empezar la vuelta i de insertion sort, ¿qué afirmación basta para concluir, al terminar, que el
arreglo quedó ordenado y con los mismos elementos?

### Opciones
- El prefijo a[0..i) está ordenado.
- [x] El prefijo a[0..i) contiene exactamente los elementos que había al inicio en esas posiciones, ahora ordenados.
- a[i] es el mínimo de a[i..n).
- El número de inversiones baja en cada vuelta.

### Justificación
«Está ordenado» solo no alcanza: un programa que sobreescribe el prefijo con ceros también lo mantiene ordenado, así que la
salida no se sigue. Hace falta decir que es una permutación de lo original. «a[i] es el mínimo del resto» es el invariante de
selection sort y aquí es falso. Las inversiones no bajan cuando a[i] ya está en su lugar, y aun si bajaran sólo hablarían
de terminación, no de qué contiene el arreglo.

## La prueba de costo, por escrito
type: production
id: a1-01-prod-cota

Escribe, en cinco a ocho líneas, la prueba de que `primerMayorIgual` hace a lo sumo ⌊log₂ n⌋ + 1 vueltas. Nombra la cantidad
que baja y cuánto baja.

### Modelo
Sea m = hi − lo. Si a[mid] < x, el nuevo tamaño es hi − mid − 1 = ⌈m/2⌉ − 1 ≤ ⌊m/2⌋; si no, es mid − lo = ⌊m/2⌋. En los
dos casos m pasa a ser a lo sumo ⌊m/2⌋. Tras k vueltas, m ≤ ⌊n / 2^k⌋, y el lazo sigue sólo mientras m ≥ 1. Para
k = ⌊log₂ n⌋ + 1 se tiene 2^k > n, así que m = 0 y el lazo ya terminó. Cada vuelta cuesta O(1): el total es O(log n).

### Regla
La cota sale de una cantidad entera que se reduce en una fracción fija por vuelta; contar vueltas con esa cantidad es la
prueba, y el tiempo de reloj no prueba nada.

### Rúbrica
- Define la cantidad (hi − lo) y la usa en las dos ramas del if.
- Muestra que el tamaño queda en a lo sumo la mitad entera en ambas ramas.
- Concluye el número máximo de vueltas y el costo total.
