# A1-06 · Grafos, BFS, DFS y dependencias

Banco ligero de la ruta A1. La misión: modelar dependencias de órdenes, detectar ciclos y construir un orden válido, con
prueba de terminación y costo. Los recorridos completos están en ITC C6.

## Antes de leer: Kahn frente a un ciclo
type: prediccion
id: a1-06-pred-ciclo
rol: prediccion

Corres el algoritmo de Kahn (cola de nodos con grado de entrada 0) sobre órdenes donde A depende de B, B de C y C de A, más
otras diez órdenes sin problemas. ¿Qué pasa?

### Opciones
- El programa entra en un ciclo infinito
- [x] Termina, pero el orden sale con menos nodos: A, B y C nunca llegan a grado 0
- Lanza una excepción al encontrar la arista que cierra el ciclo
- Entrega todos los nodos, con A, B y C en un orden arbitrario

### Justificación
Kahn sólo saca nodos de la cola, y un nodo entra a la cola únicamente cuando su grado llega a 0. Los del ciclo siempre
conservan una dependencia pendiente dentro del ciclo, así que nunca entran: la cola se vacía y el algoritmo termina con 10
nodos de 13. Esa diferencia de tamaño es la detección del ciclo. No hay ciclo infinito porque cada nodo entra a la cola a lo
sumo una vez.

## Orden de órdenes, desvanecido
type: desvanecido
id: a1-06-desv-kahn
lang: javascript

Completa `ordenValido(n, aristas)`: hay n órdenes (0 a n − 1) y cada arista [u, v] dice «u antes que v». Devuelve un orden
válido con Kahn, usando una cola FIFO que empieza con los nodos de grado 0 en orden creciente, o `null` si hay un ciclo.

### Pasos
1. Arma la lista de adyacencia y cuenta el grado de entrada de cada nodo.
2. Encola, en orden creciente, los nodos con grado 0.
3. Saca de la cola, agrega al orden y resta 1 al grado de cada vecino; encola los que llegan a 0.
4. Si el orden tiene menos de n nodos, hay un ciclo: devuelve null.
5. Demuestra que el algoritmo termina y cuesta O(V + E).

### Plantilla
```javascript
function ordenValido(n, aristas) {
  const ady = Array.from({ length: n }, () => []);
  // <paso 1>
  const grado = new Array(n).fill(0);
  for (const [u, v] of aristas) {
    ady[u].push(v);
    grado[v]++;
  }
  // </paso 1>
  const cola = [];
  // <paso 2>
  for (let i = 0; i < n; i++) if (grado[i] === 0) cola.push(i);
  // </paso 2>
  const orden = [];
  let cabeza = 0;
  while (cabeza < cola.length) {
    // <paso 3>
    const u = cola[cabeza++];
    orden.push(u);
    for (const v of ady[u]) {
      grado[v]--;
      if (grado[v] === 0) cola.push(v);
    }
    // </paso 3>
  }
  // <paso 4>
  return orden.length === n ? orden : null;
  // </paso 4>
}
```

## Ciclo con tres colores
type: code
id: a1-06-code-ciclo
tiempo: 12

Devuelve `true` si el grafo dirigido de n nodos tiene un ciclo. Usa DFS con tres estados: sin visitar, en curso y
terminado. Un diamante sin ciclo debe dar `false`.

### Especificación
Marca el nodo en curso al entrar. Para cada vecino: si está en curso, hay ciclo; si no está visitado, recorre desde él. Al
terminar sus vecinos, márcalo terminado. Arranca desde cada nodo sin visitar, porque el grafo puede tener varias componentes.

### Firma
```javascript
function tieneCiclo(n, aristas) {
  // tu código
}
```
```python
def tiene_ciclo(n, aristas):
    # tu código
    pass
```

### Casos
```json
[
  { "input": [3, []], "expected": false },
  { "input": [3, [[0, 1], [1, 2]]], "expected": false },
  { "input": [3, [[0, 1], [1, 2], [2, 0]]], "expected": true },
  { "input": [4, [[0, 1], [0, 2], [1, 3], [2, 3]]], "expected": false },
  { "input": [1, [[0, 0]]], "expected": true },
  { "input": [4, [[0, 1], [2, 3], [3, 2]]], "expected": true },
  { "input": [5, [[0, 1], [1, 2], [0, 2], [3, 4]]], "expected": false }
]
```

### Solución
```javascript
function tieneCiclo(n, aristas) {
  const ady = Array.from({ length: n }, () => []);
  for (const [u, v] of aristas) ady[u].push(v);
  const color = new Array(n).fill(0);
  const visita = (u) => {
    color[u] = 1;
    for (const v of ady[u]) {
      if (color[v] === 1) return true;
      if (color[v] === 0 && visita(v)) return true;
    }
    color[u] = 2;
    return false;
  };
  for (let i = 0; i < n; i++) if (color[i] === 0 && visita(i)) return true;
  return false;
}
```
```python
def tiene_ciclo(n, aristas):
    ady = [[] for _ in range(n)]
    for u, v in aristas:
        ady[u].append(v)
    color = [0] * n

    def visita(u):
        color[u] = 1
        for v in ady[u]:
            if color[v] == 1:
                return True
            if color[v] == 0 and visita(v):
                return True
        color[u] = 2
        return False

    return any(color[i] == 0 and visita(i) for i in range(n))
```

### Pistas
- «Visitado» no basta: en el diamante, el nodo 3 ya está visitado cuando llegas por la segunda rama y no hay ciclo.
- Un lazo u → u es un ciclo: el nodo está en curso cuando lo encuentras como vecino.

## La dirección de la flecha
type: multiple_choice
id: a1-06-mc-flecha
rol: recuperacion

Sin volver al libro: modelas «la orden v depende de la orden u» y quieres que Kahn entregue primero lo que se puede hacer
primero. ¿Qué arista dibujas?

### Opciones
- [x] u → v: la arista va de la dependencia hacia lo que la necesita, y un orden válido deja toda arista apuntando hacia adelante.
- v → u, porque v es la que «apunta» a lo que necesita; Kahn entrega igual el orden de ejecución.
- Una arista no dirigida entre u y v, porque la dependencia es mutua.
- Da igual la dirección: un orden topológico es válido en los dos sentidos.

### Justificación
Kahn empieza por los nodos sin aristas de entrada. Con u → v, esos son las órdenes que no dependen de nada, así que salen
primero, como debe ser. Con v → u el algoritmo sigue funcionando pero entrega el orden al revés, y hay que invertirlo; no
es «igual». Una arista no dirigida pierde justo la información de quién va antes.

## Terminación y costo, por escrito
type: production
id: a1-06-prod-prueba

Demuestra, en cinco a siete líneas, que el algoritmo de Kahn termina, cuesta O(V + E) y detecta ciclos.

### Modelo
Un nodo entra a la cola sólo cuando su grado de entrada llega a 0. El grado empieza en un entero no negativo y sólo baja, así
que llega a 0 a lo sumo una vez: cada nodo entra y sale de la cola a lo sumo una vez, y el lazo termina tras a lo sumo V
vueltas. Al sacar un nodo se recorren sus aristas de salida una vez; en total, E aristas. El costo es O(V + E). Si al final
faltan nodos, cada uno conserva una dependencia hacia otro que también falta; siguiendo esas dependencias en un conjunto
finito se repite un nodo, y eso es un ciclo.

### Regla
Para probar que un algoritmo de grafos termina se nombra algo que sólo baja (aquí, el grado) y se cuenta cuántas veces cada
nodo y cada arista se procesan.

### Rúbrica
- Usa que el grado sólo baja para acotar las entradas a la cola.
- Cuenta nodos y aristas por separado para llegar a O(V + E).
- Explica por qué los nodos que faltan forman o contienen un ciclo.

## Giro: entre las listas, la de plazo más próximo
type: giro
id: a1-06-giro-plazos
rol: transferencia

Cambia una restricción: cada orden tiene un plazo, y cuando varias están listas a la vez hay que empezar la de plazo más
próximo. Además, si hay un ciclo, operación quiere saber **qué** órdenes lo forman, no sólo que existe. Rediseña el
algoritmo y su costo.

### Rúbrica
- Cambia la cola FIFO por un heap de mínimos por plazo, con desempate definido, y da el costo O((V + E) log V).
- Mantiene la prueba de terminación: el grado sigue bajando y cada nodo entra al heap a lo sumo una vez.
- Para reportar el ciclo, recorre los nodos que quedaron fuera siguiendo dependencias pendientes (o con DFS de tres colores) y devuelve la lista concreta.
- Aclara que elegir por plazo entre las listas no garantiza cumplir todos los plazos y dice qué faltaría para comprobarlo.
