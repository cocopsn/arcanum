# A2-06 · Repo-debug con IA autorizada

Banco ligero de la ruta A2. La misión: localizar y corregir bugs sembrados con límites explícitos al asistente, y entregar
diff, reproducciones y pruebas. Localizar y parchar bajo reloj está en OA-12.

## Antes de leer: el lote compartido
type: prediccion
id: a2-06-pred-lote
rol: prediccion

¿Qué imprime este programa de Python?

```python
def agregar(item, lote=[]):
    lote.append(item)
    return lote

agregar(1)
print(agregar(2))
```

### Opciones
- [2]
- [x] [1, 2]
- [1]
- Lanza un error porque lote no se pasó

### Justificación
El valor por omisión `[]` se evalúa una sola vez, cuando se define la función, y todas las llamadas sin `lote` comparten esa
misma lista. La primera llamada deja [1] dentro y la segunda agrega 2. La corrección habitual es `lote=None` y crear la lista
dentro de la función. No hay error: omitir un argumento con valor por omisión es válido.

## Bug sembrado: la paginación
type: code
id: a2-06-code-paginar
tiempo: 10

Esta función, que debía devolver la página `pagina` (empezando en 1) de tamaño `tam`, tiene un bug sembrado:

```python
def paginar(items, tam, pagina):
    return items[pagina * tam : pagina * tam + tam]
```

Escribe la versión corregida. Si `tam` no es positivo o `pagina` es menor que 1, devuelve una lista vacía. Los casos incluyen
la reproducción mínima del bug.

### Especificación
La página p empieza en (p − 1) · tam y termina antes de p · tam. Una página fuera de rango da lista vacía. Valida tam y pagina
antes de cortar.

### Firma
```javascript
function paginar(items, tam, pagina) {
  // tu código
}
```
```python
def paginar(items, tam, pagina):
    # tu código
    pass
```

### Casos
```json
[
  { "input": [[1, 2, 3, 4, 5], 2, 1], "expected": [1, 2] },
  { "input": [[1, 2, 3, 4, 5], 2, 3], "expected": [5] },
  { "input": [[1, 2, 3, 4, 5], 2, 4], "expected": [] },
  { "input": [[], 3, 1], "expected": [] },
  { "input": [[1, 2, 3], 3, 1], "expected": [1, 2, 3] },
  { "input": [[1, 2, 3], 2, 0], "expected": [] },
  { "input": [[1, 2, 3], 0, 1], "expected": [] }
]
```

### Solución
```javascript
function paginar(items, tam, pagina) {
  if (tam <= 0 || pagina < 1) return [];
  return items.slice((pagina - 1) * tam, pagina * tam);
}
```
```python
def paginar(items, tam, pagina):
    if tam <= 0 or pagina < 1:
        return []
    return items[(pagina - 1) * tam : pagina * tam]
```

### Pistas
- La reproducción mínima es la página 1: el bug la convierte en la página 2.
- Con tam = 0 el corte sería vacío de todos modos, pero la validación explícita documenta la regla.

## Bug sembrado: el día del reporte
type: code
id: a2-06-code-dia
tiempo: 15

El reporte agrupa ventas por día tomando la fecha UTC de cada marca de tiempo, pero el negocio opera con un desfase fijo de
`desfaseHoras` respecto de UTC (por ejemplo −6). Corrige la función: cada venta es `[instanteUTC, monto]` y la salida es una
lista de `[día local AAAA-MM-DD, total]` ordenada por día.

### Especificación
Convierte el instante UTC a la hora local sumando el desfase en horas, toma la fecha resultante y acumula el monto en ese
día. Devuelve los días ordenados de menor a mayor.

### Firma
```javascript
function ventasPorDia(ventas, desfaseHoras) {
  // tu código
}
```
```python
def ventas_por_dia(ventas, desfase_horas):
    # tu código
    pass
```

### Casos
```json
[
  { "input": [[], -6], "expected": [] },
  { "input": [[["2026-11-01T03:00:00Z", 10]], -6], "expected": [["2026-10-31", 10]] },
  { "input": [[["2026-11-01T07:00:00Z", 5], ["2026-11-01T05:59:00Z", 7]], -6], "expected": [["2026-10-31", 7], ["2026-11-01", 5]] },
  { "input": [[["2026-11-01T12:00:00Z", 1], ["2026-11-01T13:00:00Z", 2]], 0], "expected": [["2026-11-01", 3]] },
  { "input": [[["2026-12-31T20:00:00Z", 4]], 5], "expected": [["2027-01-01", 4]] }
]
```

### Solución
```javascript
function ventasPorDia(ventas, desfaseHoras) {
  const tot = new Map();
  for (const [ts, monto] of ventas) {
    const dia = new Date(Date.parse(ts) + desfaseHoras * 3600000).toISOString().slice(0, 10);
    tot.set(dia, (tot.get(dia) || 0) + monto);
  }
  return [...tot.keys()].sort().map((d) => [d, tot.get(d)]);
}
```
```python
from datetime import datetime, timedelta

def ventas_por_dia(ventas, desfase_horas):
    tot = {}
    for ts, monto in ventas:
        t = datetime.fromisoformat(ts.replace("Z", "+00:00")) + timedelta(hours=desfase_horas)
        dia = t.date().isoformat()
        tot[dia] = tot.get(dia, 0) + monto
    return [[d, tot[d]] for d in sorted(tot)]
```

### Pistas
- La reproducción mínima es una venta a las 03:00 UTC con desfase −6: es del día anterior.
- Una segunda reproducción, 05:59 UTC, impide un parche hecho a la medida de la primera.

## El parche del asistente
type: multiple_choice
id: a2-06-mc-parche
rol: recuperacion

Sin volver al libro: para el bug del día del reporte, el asistente propone cambiar la fecha esperada en la prueba, y la
prueba pasa. ¿Qué haces?

### Opciones
- Lo aceptas: la prueba está en verde y el tiempo apremia.
- [x] Lo rechazas: viola el contrato (no se cambian pruebas para que pasen), el bug sigue, y lo demuestras con una segunda reproducción que el parche no conoce.
- Lo aceptas, pero agregas un comentario de que la prueba podría estar mal.
- Borras la prueba, porque si el asistente la cambió es que no era confiable.

### Justificación
Una prueba en verde sólo vale si mide el comportamiento correcto. Cambiar la expectativa para que coincida con el bug
convierte la prueba en una foto del defecto. El contrato del asistente lo prohíbe por escrito justamente por eso, y una
segunda reproducción (otra hora cerca del cambio de día) muestra que el defecto sigue. Borrar la prueba quita la única
evidencia.

## Reporte de un bug, por escrito
type: production
id: a2-06-prod-reporte

Escribe el reporte de cierre del bug de la paginación como lo entregarías: contrato del asistente, reproducción, prueba,
diff, comprobación de que la prueba vuelve a fallar sin el parche, y la frase del mecanismo.

### Modelo
Contrato: el asistente pudo explicar el error y proponer casos; no escribió el parche ni tocó pruebas. Reproducción mínima:
paginar([1, 2, 3, 4, 5], 2, 1) devuelve [3, 4] y debía devolver [1, 2]. Prueba: página 1, última página incompleta (página 3
→ [5]) y página fuera de rango (página 4 → []). Diff: el corte pasa de items[pagina*tam : pagina*tam + tam] a
items[(pagina − 1)*tam : pagina*tam], más la validación de tam y pagina. Sin el parche, las tres pruebas fallan; con él,
pasan. Mecanismo: las páginas se numeran desde 1, pero el corte las trataba como si empezaran en 0.

### Regla
Un bug se cierra con reproducción, prueba que falla por la razón correcta, parche, prueba que pasa y la comprobación de que
vuelve a fallar sin el parche; el uso del asistente queda declarado.

### Rúbrica
- Declara qué hizo y qué no hizo el asistente.
- Da la reproducción mínima con valor obtenido y esperado.
- Muestra el diff y la comprobación de que la prueba falla sin el parche.
- Explica el mecanismo en una frase propia.
