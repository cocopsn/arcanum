## Predicción: «¿está este folio?»
type: prediccion
id: prediccion-costo-pertenencia
rol: prediccion
Tienes 50,000 folios del sistema y, por cada una de las 50,000 filas del banco, preguntas si su folio está entre los del sistema. Antes de medir nada, ¿qué estructura usarías para guardar los folios del sistema y qué costo total esperas?
### Opciones
- Una lista; el costo total es lineal porque cada `in` es una operación.
- [x] Un conjunto; cada pregunta cuesta en promedio lo mismo sin importar cuántos folios haya, así que el total es lineal en las filas del banco.
- Una lista ordenada; cada `in` usa búsqueda binaria automáticamente.
- Da igual: Python optimiza `in` igual para todas las estructuras.
### Justificación
`x in lista` recorre la lista hasta encontrar `x`, así que 50,000 preguntas sobre 50,000 folios son del orden de 2,500 millones de comparaciones en el peor caso. En un conjunto (o en las llaves de un diccionario) cada pregunta usa el hash y cuesta en promedio una cantidad constante. Python no sabe que tu lista está ordenada: `in` no hace búsqueda binaria; para eso existe el módulo `bisect`, y aun así un conjunto es más simple.

## Predicción: una lista como llave
type: prediccion
id: prediccion-llave-lista
rol: prediccion
La llave de negocio es folio más sucursal. ¿Qué pasa al ejecutar `indice = {}` y luego `indice[["A1", "S03"]] = 100`?
### Opciones
- Funciona y la llave es la lista `["A1", "S03"]`.
- Funciona, pero Python convierte la lista a cadena.
- [x] Lanza `TypeError`, porque una lista es mutable y no se puede usar como llave.
- Funciona sólo si la lista tiene exactamente dos elementos.
### Justificación
Las llaves de un diccionario deben ser inmutables y tener hash. Una lista puede cambiar después de insertarse, lo que rompería el índice, así que Python la rechaza con `TypeError: unhashable type: 'list'`. La forma correcta es una tupla: `indice[("A1", "S03")] = 100`, que sirve porque sólo contiene cadenas.

### Solución
```python
from decimal import Decimal, InvalidOperation

def conciliar(banco, sistema):
    a, ra = _leer(banco, "banco")
    b, rb = _leer(sistema, "sistema")
    comunes = a.keys() & b.keys()
    return {
        "conciliados": sum(1 for f in comunes if a[f] == b[f]),
        "solo_banco": sorted(a.keys() - b.keys()),
        "solo_sistema": sorted(b.keys() - a.keys()),
        "montos_distintos": sorted(f for f in comunes if a[f] != b[f]),
        "rechazadas": ra + rb,
    }

def _leer(filas, fuente):
    validas, rechazadas = {}, []
    for n, fila in enumerate(filas, start=1):
        if not isinstance(fila, (list, tuple)) or len(fila) != 2:
            rechazadas.append([fuente, n, "fila mal formada"])
            continue
        folio, monto = fila
        folio = folio.strip() if isinstance(folio, str) else ""
        if not folio:
            rechazadas.append([fuente, n, "sin folio"])
            continue
        try:
            valor = Decimal(monto.strip()) if isinstance(monto, str) else None
        except InvalidOperation:
            valor = None
        if valor is None or not valor.is_finite():
            rechazadas.append([fuente, n, "monto no numérico"])
            continue
        if folio in validas:
            rechazadas.append([fuente, n, "folio duplicado"])
            continue
        validas[folio] = valor
    return validas, rechazadas
```
### Pistas
- Separa la lectura (validar cada fila y construir un diccionario folio → monto) de la comparación.
- Las vistas `dict.keys()` admiten `&` y `-` como conjuntos.
- `Decimal("NaN")` no lanza error: comprueba `is_finite()`.
- Ordena las listas antes de devolverlas.

## La regla de las cuatro salidas
type: multiple_choice
id: regla-cuatro-salidas
Un conciliador reporta para el archivo A: 120 filas leídas, 100 conciliadas, 8 con monto distinto, 7 sólo en A y 0 rechazadas. ¿Qué concluyes?
### Opciones
- El reporte es correcto: no hubo filas ilegibles.
- [x] Faltan 5 filas: 100 + 8 + 7 + 0 = 115, así que el programa perdió filas sin contarlas, probablemente en un `continue` silencioso.
- Las 5 filas que faltan son duplicados y no hace falta reportarlas.
- Hay que volver a correrlo; el orden de lectura pudo cambiar el conteo.
### Justificación
Toda fila de entrada debe terminar en exactamente una salida: conciliada, monto distinto, sólo en un lado o rechazada con motivo. Si la suma no da las filas leídas, el programa descartó filas en silencio. Los duplicados son rechazos con motivo, no una excepción a la regla. Y un conciliador reproducible da el mismo conteo en cada corrida; si cambia, ese es otro defecto.

## Por qué ordenar, sin mirar
type: multiple_choice
id: recuperar-por-que-ordenar
rol: recuperacion
Sin volver al libro: ¿por qué el conciliador ordena `solo_banco` antes de devolverla, si el contenido es el mismo sin ordenar?
### Opciones
- Porque los conjuntos de Python no admiten iterarse sin ordenar.
- Porque ordenar elimina los duplicados.
- [x] Porque el orden de iteración de un conjunto de cadenas puede cambiar entre corridas (el hash de las cadenas se aleatoriza por proceso), y un reporte reproducible debe salir igual cada vez.
- Porque ordenar hace más rápida la comparación de montos.
### Justificación
Un conjunto no promete orden, y para cadenas el orden puede variar de un proceso a otro. Ordenar es la forma barata de que dos corridas sobre los mismos archivos den el mismo reporte, byte por byte, y de que un diff entre dos reportes muestre cambios reales y no ruido.

## Defensa: estructuras, mutabilidad y costo
type: production
id: defensa-estructuras
Justifica, para tu conciliador, cada estructura que usaste, qué es mutable y quién podría ver un cambio, y el costo total con N filas por lado. Después explica qué hace tu programa con un archivo vacío, con un archivo sin la columna de folio y con una fila con `NaN`.
### Modelo
«Uso un diccionario folio → `Decimal` por fuente, porque pregunto por llave y necesito el monto; las vistas de llaves me dan intersección y diferencias como conjuntos. Las listas de rechazadas son nuevas y no toco la entrada, así que quien me llama no ve sus filas cambiadas. Leer cuesta O(N) por lado y comparar cuesta O(N) en promedio; ordenar las salidas cuesta O(N log N), que domina. Archivo vacío: todos los conteos en cero y el reporte sale igual. Sin columna de folio: es un error de formato del archivo, no de una fila, así que me detengo con un mensaje que nombra la columna. `NaN`: `Decimal` lo acepta, por eso compruebo `is_finite()` y la fila sale como rechazada con su número.»
### Regla
La defensa de una estructura nombra la pregunta que responde barata, su mutabilidad y el costo total. La defensa de la robustez distingue un error de fila (se rechaza y se cuenta) de un error de archivo (se detiene con un mensaje claro).

- Dice qué es mutable y confirma que no modifica la entrada.
- Da el costo total y nombra qué parte domina.

- Distingue error de fila (rechazo contado) de error de archivo (alto con mensaje).
