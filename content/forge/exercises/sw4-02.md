## Antes de leer: diez millones de llaves
type: prediccion
id: prediccion-altura
rol: prediccion
tiempo: 2

Un B+Tree tiene nodos de unas 200 llaves y guarda diez millones de llaves en sus hojas. ¿Cuántas páginas lee aproximadamente una búsqueda puntual, de la raíz a la hoja?

### Opciones
- [x] Unas 4: con abanico 200, tres niveles internos alcanzan a 8 millones de hojas, así que basta un camino de pocos nodos.
- Unas 23, porque log₂ de diez millones es cerca de 23.
- Unas 50,000, porque hay que recorrer las hojas hasta encontrar la llave.
- Una sola, porque la raíz guarda todas las llaves.
### Justificación
El número de niveles crece con el logaritmo en base del abanico, no en base 2: 200³ = 8 millones, así que con cuatro niveles (tres internos y las hojas) sobra lugar para diez millones de llaves. log₂ sería la altura de un árbol binario. Recorrer hojas sólo pasa en una búsqueda por rango. Una raíz con todas las llaves no cabría en una página.

## El verificador de invariantes

Escribe el verificador que habría detectado el contraejemplo del libro: recibe un B+Tree y dice si cumple sus cuatro invariantes.

### Especificación
`esBMasValido(raiz, minLlaves, maxLlaves)`:
- Un nodo es `{ "hoja": true, "llaves": [...] }` o `{ "hoja": false, "llaves": [...], "hijos": [...] }`; las llaves son enteros.
- **Orden:** las llaves de cada nodo están en orden estrictamente creciente.
- **Ocupación:** ningún nodo tiene más de `maxLlaves`; todo nodo que no es la raíz tiene al menos `minLlaves`. Una raíz que es hoja puede estar vacía; una raíz interna tiene al menos 1 llave.
- **Estructura:** un nodo interno con `n` llaves tiene exactamente `n + 1` hijos.
- **Separación:** las llaves de un nodo que cuelga del hijo `i` de un interno con llaves `k` cumplen `k[i − 1] ≤ llave < k[i]` (sin cota inferior para el primer hijo ni superior para el último), y esa cota se hereda a todo su subárbol.
- **Balance:** todas las hojas están a la misma profundidad.
- Devuelve `true` si se cumplen todos y `false` si alguno falla.

### Solución
```javascript
function esBMasValido(raiz, minLlaves, maxLlaves) {
  let profundidadHojas = null;
  const valido = (nodo, bajo, alto, prof, esRaiz) => {
    const ll = nodo.llaves;
    if (!Array.isArray(ll)) return false;
    for (let i = 1; i < ll.length; i++) if (!(ll[i - 1] < ll[i])) return false;
    if (ll.length > maxLlaves) return false;
    if (!esRaiz && ll.length < minLlaves) return false;
    for (const k of ll) if ((bajo !== null && k < bajo) || (alto !== null && k >= alto)) return false;
    if (nodo.hoja) {
      if (profundidadHojas === null) profundidadHojas = prof;
      return profundidadHojas === prof;
    }
    if (esRaiz && ll.length < 1) return false;
    if (!Array.isArray(nodo.hijos) || nodo.hijos.length !== ll.length + 1) return false;
    for (let i = 0; i < nodo.hijos.length; i++) {
      const b = i === 0 ? bajo : ll[i - 1];
      const a = i === ll.length ? alto : ll[i];
      if (!valido(nodo.hijos[i], b, a, prof + 1, false)) return false;
    }
    return true;
  };
  return valido(raiz, null, null, 0, true);
}
```

    profundidad_hojas = [None]

    def valido(nodo, bajo, alto, prof, es_raiz):
        ll = nodo.get("llaves")
        if not isinstance(ll, list):
            return False
        for i in range(1, len(ll)):
            if not ll[i - 1] < ll[i]:
                return False
        if len(ll) > max_llaves:
            return False
        if not es_raiz and len(ll) < min_llaves:
            return False
        for k in ll:
            if (bajo is not None and k < bajo) or (alto is not None and k >= alto):
                return False
        if nodo.get("hoja"):
            if profundidad_hojas[0] is None:
                profundidad_hojas[0] = prof
            return profundidad_hojas[0] == prof
        if es_raiz and len(ll) < 1:
            return False
        hijos = nodo.get("hijos")
        if not isinstance(hijos, list) or len(hijos) != len(ll) + 1:
            return False
        for i, hijo in enumerate(hijos):
            b = bajo if i == 0 else ll[i - 1]
            a = alto if i == len(ll) else ll[i]
            if not valido(hijo, b, a, prof + 1, False):
                return False
        return True

    return valido(raiz, None, None, 0, True)

## La división de una hoja
type: trace
id: traza-division-hoja
tiempo: 3

Un B+Tree admite 3 llaves por nodo. Su raíz es `[10]`, con hijos `[2 5 7]` y `[10 12]`. Se inserta la llave 6. ¿Cómo queda el árbol?

### Opciones
- [x] La hoja `[2 5 6 7]` se parte en `[2 5]` y `[6 7]`, se copia 6 al padre y la raíz queda `[6 10]` con hijos `[2 5]`, `[6 7]` y `[10 12]`.
- La raíz queda `[10]` y la hoja `[2 5 6 7]`, porque el máximo se revisa sólo en la raíz.
- La raíz queda `[5 10]` con hijos `[2]`, `[6 7]` y `[10 12]`, porque la llave del medio sube y sale de la hoja.
- Se crea una raíz nueva `[10]` con dos hijos internos, porque toda división hace crecer el árbol.
### Justificación
La llave 6 va a la hoja izquierda (6 < 10), que queda `[2 5 6 7]` y se pasa del máximo. Se divide en dos mitades, `[2 5]` y `[6 7]`, y la primera llave de la mitad derecha, 6, se **copia** al padre: en las hojas la llave se queda, porque ahí están los datos. La raíz pasa a `[6 10]`, que cabe, así que el árbol no crece. Revisar el máximo sólo en la raíz rompe la ocupación. Sacar la llave del medio de la hoja es la regla de los nodos internos. El árbol sólo crece cuando se divide la raíz.

## ¿Cuándo soltar al padre?
type: multiple_choice
id: cangrejeo-latches
tiempo: 3

Un thread inserta una llave y desciende con cangrejeo de latches de escritura. Llega a un nodo interno que tiene 2 llaves, con un máximo de 3. ¿Puede soltar los latches de sus ancestros?

### Opciones
- [x] Sí: el nodo no está lleno, así que aunque su hijo se divida y le suba una llave, no se desbordará y ningún cambio se propagará más arriba.
- No: los latches de los ancestros se sueltan sólo al terminar la inserción.
- Sí, pero sólo si el nodo es una hoja.
- No: con latches de escritura nunca se suelta nada antes de llegar a la hoja.
### Justificación
Un nodo es seguro para una inserción si puede absorber una llave más sin dividirse. Con 2 de 3 llaves, cualquier división de abajo termina en él, así que los ancestros ya no pueden cambiar y retenerlos sólo bloquearía a otros threads. Esperar al final es correcto pero innecesariamente lento, porque serializa todas las inserciones en la raíz. La regla aplica a nodos internos y hojas por igual; lo que la cambia es la operación (en un borrado, seguro significa tener más llaves que el mínimo).

## Defiende la preservación de los invariantes
type: production
id: produccion-invariantes-division
tiempo: 12

Defiende que la división de una hoja en una inserción preserva los cuatro invariantes del B+Tree (orden, separación, ocupación y balance). Usa una hoja llena con llaves `k₁ < … < kₘ` y la llave nueva `x`, y explica qué pasa también si el padre se desborda.

### Modelo
*Situación:* la hoja tiene `m` llaves (el máximo) y recibe `x`, que respeta la separación de su padre (por eso se eligió esa hoja). Al agregar `x` en orden quedan `m + 1` llaves ordenadas.
*División:* se parte en una mitad izquierda `I` y una derecha `D`, ambas con al menos el mínimo (porque `m + 1` es al menos el doble del mínimo), y se copia al padre `s = min(D)` como llave guía, insertada en orden entre las guías que ya acotaban la hoja.
*Orden:* `I` y `D` son tramos de una lista ordenada; el padre sigue ordenado porque `s` cae entre las guías que acotaban la hoja original.
*Separación:* todas las llaves de `I` son `< s` y todas las de `D` son `≥ s`, que es exactamente la regla de los dos hijos nuevos; las cotas heredadas de la hoja original siguen valiendo para las dos.
*Ocupación:* las dos hojas tienen entre el mínimo y el máximo; el padre gana una llave y, si se desborda, se divide con la regla de nodos internos (la llave del medio sube), que aplica el mismo argumento un nivel más arriba.
*Balance:* `I` y `D` quedan a la profundidad de la hoja original; si la división llega a la raíz, se crea una raíz nueva y todas las hojas bajan un nivel a la vez.

### Regla
Defender una operación sobre una estructura con invariantes es mostrar, para cada invariante, por qué vale después de la operación en las partes que cambiaron y por qué las partes que no cambiaron lo siguen cumpliendo.

### Rúbrica
- Trata los cuatro invariantes por separado.
- Elige la llave guía correcta (la primera de la mitad derecha) y explica por qué se copia y no se mueve.
- Muestra que ambas mitades cumplen la ocupación mínima.
- Explica la propagación al padre y el crecimiento por la raíz.
- Argumenta que el balance se conserva porque el árbol sólo crece por arriba.
