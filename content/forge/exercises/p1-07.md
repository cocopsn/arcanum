### Solución
```javascript
function verificar_evidencia(texto, campos) {
  const motivos = ["no_encontrado", "ilegible", "remite_a_otro_documento", "contradictorio"];
  const malos = [];
  for (const c of campos) {
    let ok;
    if (c.valor === null || c.valor === undefined) {
      ok = motivos.includes(c.motivo);
    } else {
      ok = Number.isInteger(c.inicio) && Number.isInteger(c.fin) && c.inicio >= 0 && c.inicio < c.fin && c.fin <= texto.length &&
        texto.slice(c.inicio, c.fin).toLowerCase().includes(String(c.valor).toLowerCase());
    }
    if (!ok) malos.push(c.campo);
  }
  return malos.sort();
}
```
```python
def verificar_evidencia(texto, campos):
    motivos = {"no_encontrado", "ilegible", "remite_a_otro_documento", "contradictorio"}
    malos = []
    for c in campos:
        if c.get("valor") is None:
            ok = c.get("motivo") in motivos
        else:
            i, f = c.get("inicio"), c.get("fin")
            ok = (isinstance(i, int) and isinstance(f, int) and not isinstance(i, bool) and not isinstance(f, bool)
                  and 0 <= i < f <= len(texto)
                  and str(c["valor"]).lower() in texto[i:f].lower())
        if not ok:
            malos.append(c["campo"])
    return sorted(malos)
```

## «Niega alergias»
type: multiple_choice
id: negacion-alergias
tiempo: 2

En una carta sintética aparece «Niega alergias.». ¿Qué registro debe producir el extractor para el campo `alergias`?

### Opciones
- [x] Valor «sin alergias declaradas», con el tramo «Niega alergias» como evidencia.
- Valor nulo con motivo `no_encontrado`, porque no se nombra ninguna alergia.
- Valor «niega», tomado literalmente del texto.
- El campo se omite del registro, porque una negación no es un dato.
### Justificación
La negación es un hecho clínico distinto de la ausencia de información: la paciente declaró no tener alergias. Marcarla como «no encontrado» la confunde con un documento que no habla del tema; copiar «niega» no es un valor normalizado; omitirla pierde el hecho. El tramo de la negación es su evidencia.

## Contrato de campos para un documento nuevo
type: production
id: contrato-constancia
tiempo: 12

La clínica empieza a recibir **constancias de incapacidad** sintéticas (escaneadas, con sello y firma manuscrita, a veces con dos fechas: emisión e inicio de la incapacidad, y un número de días). Escribe el contrato de extracción: los campos, su normalización, qué evidencia exige cada uno, qué motivos de nulo admites y tres casos difíciles que pondrías en tu conjunto de verdad.

### Modelo
- **Campos:** `paciente` (texto), `fecha_emision` y `fecha_inicio` (ISO, separadas por su etiqueta, nunca por su orden), `dias` (entero), `diagnostico_texto` (texto tal cual, sin codificar), `firma_presente` y `sello_presente` (booleanos con su caja como evidencia).
- **Evidencia:** todo valor no nulo con documento, página y tramo o caja; `dias` con el tramo del número y la palabra «días».
- **Motivos de nulo:** `no_encontrado`, `ilegible`, `remite_a_otro_documento`, `contradictorio`.
- **Casos difíciles:** (1) «inicio: a partir de mañana» (fecha relativa: nulo `contradictorio` o derivada con la fecha de emisión y tramo de las dos, según el contrato); (2) número de días escrito en letra y en número que no coinciden («tres (5) días»): `contradictorio`; (3) firma manuscrita que invade el campo de fecha: la fecha queda `ilegible` si no se lee sin adivinar.
### Regla
El contrato de extracción exige evidencia para todo valor y un motivo cerrado para todo nulo, separa los valores por su etiqueta y no por su posición, y define de antemano qué hacer con fechas relativas y contradicciones. Nada se completa con valores frecuentes ni con otras fuentes sin su propia procedencia.
### Rúbrica
- Lista los campos con su normalización.
- Exige evidencia para cada valor no nulo y motivos cerrados para los nulos.
- Separa las dos fechas por su etiqueta.
- Incluye al menos tres casos difíciles concretos con el registro esperado.
- Ningún campo se rellena con un valor que no está en el documento.
