# A1-07 · Greedy, rutas y optimización

Banco ligero de la ruta A1. La misión: resolver una asignación de recursos con dos enfoques y un caso adversarial, y derivar
cuándo el greedy es correcto. La teoría está en CP4 y en ITC C7.

## Antes de leer: ¿qué regla codiciosa?
type: prediccion
id: a1-07-pred-regla
rol: prediccion

Una cuadrilla atiende un trabajo a la vez y quieres el máximo número de trabajos sin traslape. ¿Qué regla, aplicada en
orden, da siempre el óptimo?

### Opciones
- Tomar primero el que empieza antes
- Tomar primero el más corto
- [x] Tomar primero el que termina antes
- Tomar primero el que choca con menos trabajos

### Justificación
Terminar antes deja libre la mayor parte del tiempo restante, y el argumento de intercambio lo prueba: cualquier solución
óptima puede cambiar su primer trabajo por el que termina antes sin crear traslapes. «Empieza antes» falla con un trabajo
largo que empieza temprano; «el más corto» falla con [1,5), [4,7), [6,10); y «menos choques» también tiene contraejemplos,
aunque más grandes.

## Máximo de trabajos, desvanecido
type: desvanecido
id: a1-07-desv-intervalos
lang: javascript

Completa `maxTrabajos(intervalos)`: cada intervalo es [inicio, fin) y la cuadrilla atiende uno a la vez. Devuelve el máximo
número de trabajos compatibles con el greedy por fin más temprano.

### Pasos
1. Ordena una copia de los intervalos por fin creciente.
2. Inicializa el último fin para que el primer trabajo siempre sea compatible.
3. Toma el trabajo si empieza cuando el último tomado ya terminó, y actualiza el último fin.
4. Escribe el argumento de intercambio que prueba que el greedy es óptimo.

### Plantilla
```javascript
function maxTrabajos(intervalos) {
  // <paso 1>
  const orden = intervalos.slice().sort((x, y) => x[1] - y[1]);
  // </paso 1>
  // <paso 2>
  let fin = -Infinity;
  // </paso 2>
  let cuenta = 0;
  for (const [ini, f] of orden) {
    // <paso 3>
    if (ini >= fin) {
      cuenta++;
      fin = f;
    }
    // </paso 3>
  }
  return cuenta;
}
```

### Casos

[
  { "input": [[]], "expected": 0 },
  { "input": [[[1, 5]]], "expected": 1 },
  { "input": [[[1, 5], [4, 7], [6, 10]]], "expected": 2 },
  { "input": [[[0, 3], [3, 6], [6, 9]]], "expected": 3 },
  { "input": [[[0, 10], [1, 2], [3, 4], [5, 6]]], "expected": 3 },

- 1: 3
- 2: 1, 3
- 3: 1, 2, 3, 4

### Rúbrica
- Toma una solución óptima cualquiera y su primer trabajo s, y lo compara con el trabajo g que termina antes.
- Muestra que cambiar s por g no crea traslapes porque g termina no después que s.
- Concluye que existe una solución óptima con la elección greedy y que el argumento se repite sobre lo que queda.

### Casi correcta
```javascript
function maxTrabajos(intervalos) {
  const orden = intervalos.slice().sort((x, y) => x[1] - x[0] - (y[1] - y[0]));
  const tomados = [];
  for (const [ini, fin] of orden) {
    if (tomados.every(([a, b]) => fin <= a || ini >= b)) tomados.push([ini, fin]);
  }
  return tomados.length;
}
```

## Distancias con Dijkstra

### Casos
```json
[
  { "input": [1, [], 0], "expected": [0] },
  { "input": [3, [[0, 1, 4], [0, 2, 1], [2, 1, 2]], 0], "expected": [0, 3, 1] },
  { "input": [4, [[0, 1, 1], [1, 2, 1], [0, 2, 5]], 0], "expected": [0, 1, 2, null] },
  { "input": [3, [[1, 0, 1]], 0], "expected": [0, null, null] },
  { "input": [5, [[0, 1, 2], [0, 2, 9], [1, 2, 3], [2, 3, 1], [1, 3, 8], [3, 4, 2]], 0], "expected": [0, 2, 5, 6, 8] },

  { "input": [2, [[0, 1, 7], [0, 1, 3]], 0], "expected": [0, 3] }
]
```

### Solución
```javascript
function distancias(n, aristas, s) {
  const ady = Array.from({ length: n }, () => []);
  for (const [u, v, w] of aristas) ady[u].push([v, w]);
  const dist = new Array(n).fill(Infinity);
  const fijo = new Array(n).fill(false);
  dist[s] = 0;
  for (let vuelta = 0; vuelta < n; vuelta++) {
    let u = -1;
    for (let i = 0; i < n; i++) {
      if (!fijo[i] && dist[i] < Infinity && (u === -1 || dist[i] < dist[u])) u = i;
    }
    if (u === -1) break;
    fijo[u] = true;
    for (const [v, w] of ady[u]) if (dist[u] + w < dist[v]) dist[v] = dist[u] + w;
  }
  return dist.map((d) => (d === Infinity ? null : d));
}
```
```python
import heapq

def distancias(n, aristas, s):
    ady = [[] for _ in range(n)]
    for u, v, w in aristas:
        ady[u].append((v, w))
    dist = [None] * n
    dist[s] = 0
    fijo = [False] * n
    h = [(0, s)]
    while h:
        d, u = heapq.heappop(h)
        if fijo[u]:
            continue
        fijo[u] = True
        for v, w in ady[u]:
            nd = d + w
            if dist[v] is None or nd < dist[v]:
                dist[v] = nd
                heapq.heappush(h, (nd, v))
    return dist
```

### Pistas
- Un nodo inalcanzable nunca recibe distancia: conviértelo en null al final.
- Con aristas paralelas basta relajar todas; gana la menor.

## Monedas que engañan
type: multiple_choice
id: a1-07-mc-monedas
rol: recuperacion

Sin volver al libro: con monedas de 1, 3 y 4 hay que pagar 6 usando el mínimo de monedas. ¿Qué hace el greedy «la moneda más
grande que quepa»?

### Opciones
- Da el óptimo, 2 monedas, porque siempre conviene la moneda más grande.
- [x] Da 3 monedas (4 + 1 + 1), y el óptimo es 2 (3 + 3): no hay argumento de intercambio para este sistema de monedas.
- No termina, porque 6 no es múltiplo de 4.
- Da 6 monedas de 1, porque empieza por la más chica.

### Justificación
El greedy toma 4, quedan 2 y sólo cabe 1 dos veces: 3 monedas. 3 + 3 usa 2. El greedy funciona en algunos sistemas de
monedas y en otros no; aquí cambiar el 4 por un 3 mejora la solución, así que el intercambio que haría falta no existe. El
caso general se resuelve con programación dinámica.

## El intercambio, por escrito
type: production
id: a1-07-prod-intercambio

Explica, en cinco a siete líneas, cómo decides si un greedy es correcto para un problema nuevo de asignación, y qué haces si
no logras probarlo.

### Modelo
Busco un argumento de intercambio: tomo una solución óptima cualquiera y muestro que puedo cambiar uno de sus elementos por la
elección greedy sin empeorarla y sin romper restricciones; si lo consigo para la primera elección y el problema que queda es
del mismo tipo, el greedy es óptimo por inducción. Si no lo consigo, escribo una búsqueda exhaustiva para entradas pequeñas
y comparo contra miles de casos aleatorios: un contraejemplo descarta el greedy y apunta al método correcto (programación
dinámica, flujo o búsqueda). Ningún número de casos que pasan prueba nada por sí solo.

### Regla
Un greedy se acepta con un argumento de intercambio o se descarta con un contraejemplo; las pruebas que pasan no lo
demuestran.

### Rúbrica
- Describe el argumento de intercambio sobre una solución óptima arbitraria.
- Usa una referencia exhaustiva en tamaños pequeños para buscar contraejemplos.
- Dice que pasar pruebas no demuestra correctitud y nombra el método alternativo.

## Dijkstra frente a una arista negativa
type: multiple_choice
id: a1-07-mc-negativa

Grafo dirigido: s → a con peso 1, s → b con peso 3, b → a con peso −3 y a → c con peso 1. ¿Qué distancia a c reporta
Dijkstra, y cuál es la verdadera?

### Opciones
- Reporta 1, que es la verdadera
- [x] Reporta 2: fija c por s → a → c antes de procesar b; la verdadera es 1, por s → b → a → c
- Reporta −2, porque suma los pesos negativos
- No termina, porque la arista negativa crea un ciclo

### Justificación
Dijkstra fija a (1), relaja a → c y fija c con 2, porque 2 < 3. Sólo después procesa b y descubre que a vale 0. Aunque alguna
versión actualice la distancia de a, c ya se fijó con el valor viejo y nadie vuelve a relajar a → c. El argumento de que un
nodo fijado no puede mejorar necesita pesos no negativos. No hay ciclo: ninguna arista vuelve a s ni a b. Bellman-Ford da 1.
