# A1-03 · Stacks, queues y ventanas

Banco ligero de la ruta A1. La misión: procesar una secuencia con ventana móvil y cola monótona, y justificar que cada
elemento entra y sale una cantidad acotada de veces. La teoría de amortización está en ITC C2.

## Antes de leer: ¿cuántas salidas de la cola?
type: prediccion
id: a1-03-pred-salidas
rol: prediccion

Calculas el máximo de cada ventana de tamaño k = 1,000 sobre n = 1,000,000 de lecturas con una cola monótona de índices.
Sumando todas las ventanas, ¿cuántas veces como máximo sale un índice de la cola?

### Opciones
- [x] A lo sumo n, es decir, un millón
- Alrededor de n · k, es decir, mil millones
- Alrededor de n · log k
- Exactamente k por ventana

### Justificación
Cada índice entra una sola vez y, una vez fuera, no vuelve; por eso sale a lo sumo una vez, por el frente o por el final.
El total de salidas es a lo sumo n, aunque una ventana concreta pueda sacar muchos. n · k es el costo de recalcular cada
ventana desde cero, y n · log k es el de un heap.

## Máximo por ventana, desvanecido
type: desvanecido
id: a1-03-desv-ventana
lang: javascript

Completa `maxVentana(a, k)`: devuelve el máximo de cada ventana de tamaño k, de izquierda a derecha, en O(n). La cola guarda
índices; `cabeza` marca su frente para no pagar `shift`.

### Pasos
1. Si el índice del frente ya salió de la ventana [i − k + 1, i], avanza la cabeza.
2. Saca del final los índices cuyo valor es menor o igual que a[i]: ya no pueden ser máximos.
3. Agrega i al final de la cola.
4. Cuando la primera ventana está completa, emite el valor del frente.
5. Explica por qué el total de operaciones es O(n) aunque un paso saque muchos índices.

### Plantilla
```javascript
function maxVentana(a, k) {
  const dq = [];
  let cabeza = 0;
  const out = [];
  for (let i = 0; i < a.length; i++) {
    // <paso 1>
    if (cabeza < dq.length && dq[cabeza] <= i - k) cabeza++;
    // </paso 1>
    // <paso 2>
    while (dq.length > cabeza && a[dq[dq.length - 1]] <= a[i]) dq.pop();
    // </paso 2>
    // <paso 3>
    dq.push(i);
    // </paso 3>
    // <paso 4>
    if (i >= k - 1) out.push(a[dq[cabeza]]);
    // </paso 4>
  }
  return out;
}
```

## Siguiente mayor con pila monótona
type: code
id: a1-03-code-siguiente-mayor
tiempo: 10

Para cada posición i devuelve el índice del primer elemento a su derecha estrictamente mayor que a[i], o −1 si no existe.
Hazlo en O(n) con una pila de índices.

### Especificación
Recorre de izquierda a derecha. Mientras la cima de la pila tenga un valor menor que a[i], esa cima encontró su siguiente
mayor en i: sácala y anótalo. Después apila i. Lo que queda en la pila al final se queda con −1.

### Firma
```javascript

  // tu código
}
```
```python
def siguiente_mayor(a):
    # tu código
    pass
```

### Casos
```json
[
  { "input": [[]], "expected": [] },
  { "input": [[1]], "expected": [-1] },
  { "input": [[2, 1, 3]], "expected": [2, 2, -1] },
  { "input": [[3, 2, 1]], "expected": [-1, -1, -1] },
  { "input": [[1, 1, 2]], "expected": [2, 2, -1] },
  { "input": [[5, 7, 1, 2, 6]], "expected": [1, -1, 3, 4, -1] }
]
```

### Solución
```javascript
function siguienteMayor(a) {
  const res = new Array(a.length).fill(-1);
  const pila = [];
  for (let i = 0; i < a.length; i++) {
    while (pila.length && a[pila[pila.length - 1]] < a[i]) res[pila.pop()] = i;
    pila.push(i);
  }
  return res;
}
```
```python
def siguiente_mayor(a):
    res = [-1] * len(a)
    pila = []
    for i, v in enumerate(a):
        while pila and a[pila[-1]] < v:
            res[pila.pop()] = i
        pila.append(i)
    return res
```

### Pistas
- La pila queda con valores no crecientes de abajo hacia arriba.
- Cada índice se apila una vez y se desapila a lo sumo una vez.

## Una lista como cola
type: multiple_choice
id: a1-03-mc-cola
rol: recuperacion

Sin volver al libro: en Python implementas la cola de la ventana con una lista, agregas con `append` y sacas del frente con
`pop(0)`. ¿Qué pasa con n = 10^6 elementos?

### Opciones
- Nada: `pop(0)` cuesta O(1) igual que `pop()`.
- [x] Cada `pop(0)` desplaza los elementos restantes, así que el total puede llegar a O(n²); `collections.deque` saca del frente en O(1).
- Lanza un error cuando la lista pasa de cierto tamaño.
- Es más rápido que `deque` porque la lista ocupa memoria contigua.

### Justificación
Una lista de Python guarda sus elementos contiguos; quitar el primero obliga a mover todos los demás una posición. Repetido
n veces, eso es cuadrático. `deque` está hecho para agregar y sacar por las dos puntas en tiempo constante, que es justo lo
que pide una cola monótona. La memoria contigua ayuda a recorrer la lista, pero no evita el desplazamiento.

## El argumento amortizado, por escrito
type: production
id: a1-03-prod-amortizado

Escribe, en cuatro a seis líneas, por qué `maxVentana` corre en O(n) aunque el `while` de un paso pueda sacar muchos índices.

### Modelo
Cada índice i entra a la cola exactamente una vez (en el paso i). Una vez fuera, por el frente o por el final, no vuelve a
entrar. Entonces el número total de salidas es a lo sumo n, y el de entradas es n. Cada vuelta del for hace O(1) trabajo
además de sus salidas, así que el total es O(n) + O(número de salidas) = O(n). Un paso caro sólo gasta salidas que ningún
otro paso puede volver a gastar.

### Regla
Cuando el costo por paso no está acotado, se cuenta por elemento: si cada elemento entra y sale una cantidad acotada de
veces, el total es lineal.

### Rúbrica
- Cuenta entradas y salidas por índice.
- Dice que un índice que sale no vuelve a entrar.
- Concluye O(n) total y aclara que un paso aislado puede costar más.
