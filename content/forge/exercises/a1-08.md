# A1-08 · DP y transferencia

Banco ligero de la ruta A1. La misión: resolver una asignación con restricciones escribiendo estado y transición antes del
código, y reconstruir la recurrencia cuando cambia una restricción. La teoría completa está en ITC C8.

## Antes de leer: recursión sin memoria
type: prediccion
id: a1-08-pred-llamadas
rol: prediccion

Escribes `mejor(j) = máx(mejor(j − 1), pago(j) + mejor(p(j)))` como recursión directa, sin guardar resultados. Tienes 40
trabajos que no se traslapan entre sí, así que p(j) = j − 1 para todos. ¿Cuántas llamadas hace `mejor(40)`, más o menos?

### Opciones
- Unas 40
- Unas 1,600
- [x] Del orden de un billón (2^40 ≈ 1.1 × 10^12)
- Unas 200, como n log n

### Justificación
Con p(j) = j − 1, cada llamada a mejor(j) llama dos veces a mejor(j − 1): una por «no tomarlo» y otra por «tomarlo». El
árbol de llamadas se duplica en cada nivel y tiene unas 2^40 hojas. Con memoria cada subproblema se calcula una vez y son 41
llamadas útiles. Esa diferencia es la programación dinámica.

## Asignación con pago, desvanecida
type: desvanecido
id: a1-08-desv-pago
lang: javascript

Completa `maxPago(trabajos)`: cada trabajo es [inicio, fin, pago] con intervalo [inicio, fin). Una cuadrilla, un trabajo a la
vez. Devuelve el mayor pago total posible.

### Pasos
1. Ordena una copia por fin creciente.
2. Crea la tabla dp de tamaño n + 1 con dp[0] = 0: dp[j] es el mejor pago con los primeros j trabajos.
3. Con búsqueda binaria, cuenta cuántos de los primeros i trabajos terminan antes de que empiece el trabajo i: ese es p.
4. Aplica la transición: dp[i + 1] es el máximo entre no tomar el trabajo y tomarlo más dp[p].
5. Estado: dp[j] es el mejor pago con los primeros j trabajos en orden de fin. Relación: máx(dp[j − 1], pago(j) + dp[p(j)]). Orden: j creciente, porque p(j) < j. Base: dp[0] = 0.

### Plantilla
```javascript
function maxPago(trabajos) {
  // <paso 1>
  const t = trabajos.slice().sort((x, y) => x[1] - y[1]);
  // </paso 1>
  const n = t.length;
  // <paso 2>
  const dp = new Array(n + 1).fill(0);
  // </paso 2>
  for (let i = 0; i < n; i++) {
    // <paso 3>
    let lo = 0;
    let hi = i;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (t[mid][1] <= t[i][0]) lo = mid + 1;
      else hi = mid;
    }
    // </paso 3>
    // <paso 4>
    dp[i + 1] = Math.max(dp[i], t[i][2] + dp[lo]);
    // </paso 4>
  }
  return dp[n];
}
```

### Casos

  { "input": [[1, 3, 4], 6], "expected": 2 },
  { "input": [[2], 3], "expected": -1 },
  { "input": [[1], 0], "expected": 0 },
  { "input": [[1, 5, 10, 25], 30], "expected": 2 },

### Solución
```javascript
function minMonedas(monedas, total) {
  const dp = new Array(total + 1).fill(Infinity);
  dp[0] = 0;
  for (let t = 1; t <= total; t++) {
    for (const m of monedas) {
      if (m <= t && dp[t - m] + 1 < dp[t]) dp[t] = dp[t - m] + 1;
    }
  }
  return dp[total] === Infinity ? -1 : dp[total];
}
```
```python
def min_monedas(monedas, total):
    inf = float("inf")
    dp = [0] + [inf] * total
    for t in range(1, total + 1):
        for m in monedas:
            if m <= t and dp[t - m] + 1 < dp[t]:
                dp[t] = dp[t - m] + 1
    return -1 if dp[total] == inf else dp[total]
```

### Pistas
- Con monedas 1, 3 y 4 el greedy da 3 monedas para 6; la tabla da 2.
- Un total inalcanzable se queda en infinito: tradúcelo a −1 al final.

## El orden de cálculo
type: multiple_choice
id: a1-08-mc-orden
rol: recuperacion

Sin volver al libro: con dp[j] = máx(dp[j − 1], pago(j) + dp[p(j)]) y los trabajos ordenados por fin, ¿qué orden de cálculo
es válido para llenar la tabla de abajo hacia arriba?

### Opciones
- [x] j creciente, porque p(j) < j y j − 1 < j: todo lo que dp[j] necesita ya está calculado.
- j decreciente, porque el problema original es dp[n].
- Cualquier orden, porque la transición es un máximo y el máximo es conmutativo.
- Primero los trabajos que más pagan, para que el máximo se estabilice antes.

### Justificación
Un orden de cálculo válido es un orden topológico del grafo de dependencias entre subproblemas. Aquí cada dp[j] depende de
índices menores, así que j creciente funciona. Ir de n hacia abajo pediría valores aún no calculados. Que el máximo sea
conmutativo no cambia qué celdas necesitas ya listas, y ordenar por pago no respeta las dependencias.

## SRTBOT, por escrito
type: production
id: a1-08-prod-srtbot

Escribe SRTBOT para esta variante, sin código: cada trabajo dura un día completo, hay a lo sumo un trabajo por día, cada día
d tiene varios trabajos candidatos con pagos distintos, y no se pueden tomar trabajos en dos días seguidos.

### Modelo
Subproblema: mejor(d) = el mayor pago usando sólo los días 1..d. Relación: mejor(d) = máx(mejor(d − 1), máx_pago(d) +
mejor(d − 2)), porque si trabajo el día d no puedo trabajar el d − 1, y de los candidatos del día d sólo conviene el que más
paga. Orden: d creciente. Base: mejor(0) = 0 y mejor(−1) = 0. Original: mejor(D). Tiempo: O(D + número de candidatos), por
el máximo de cada día.

### Regla
El estado guarda exactamente lo que el resto de las decisiones necesita saber del pasado; aquí basta saber hasta qué día se
decidió, porque la regla de días seguidos se resuelve saltando a d − 2.

### Rúbrica
- Define el subproblema con su significado en palabras.
- La relación cubre las dos opciones del día d y respeta la regla de días seguidos.
- Da orden, casos base, problema original y tiempo.

## El costo de la tabla de monedas
type: multiple_choice
id: a1-08-mc-costo

`minMonedas` llena dp[0..T] y, para cada t, prueba las m denominaciones. ¿Cuántos subproblemas hay y cuál es el costo total?

### Opciones
- 2^T subproblemas, porque cada moneda se usa o no se usa
- [x] T + 1 subproblemas y O(T · m) de tiempo, porque cada uno prueba m transiciones
- m subproblemas y O(m log T) de tiempo
- T subproblemas y O(T) de tiempo, sin importar m

### Justificación
El estado es el total por pagar, de 0 a T: T + 1 subproblemas. Cada uno toma el mínimo sobre m monedas: O(m) por subproblema
y O(T · m) en total. Es pseudopolinomial: depende del valor de T, no de cuántos dígitos tiene. 2^T sería la recursión sin
memoria, y ignorar m olvida el costo de la transición.

function formasDePagar(monedas, total) {
  const dp = new Array(total + 1).fill(0);
  dp[0] = 1;

    for (let t = m; t <= total; t++) dp[t] += dp[t - m];

  return dp[total];
}
