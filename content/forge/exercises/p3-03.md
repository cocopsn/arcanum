## La regla de reasignación con errores con nombre
type: code
id: validar-reasignacion
tiempo: 18

Escribe `validar_reasignacion(entrada)`. `entrada` tiene `cita` (`estado`, `especialidad`, `inicio`, `fin`), `medico` (`especialidad`, `activo`), `agenda` (lista de `{ inicio, fin }` del médico destino) y `ausencias` (lista de `{ inicio, fin }`); los tiempos son minutos desde medianoche. Devuelve `{ ok: true }` o `{ ok: false, error }`, revisando **en este orden**:

1. `ENTRADA_INVALIDA` si falta `cita` o `medico`, o si `cita.inicio >= cita.fin`;
2. `CITA_NO_PROGRAMADA` si `cita.estado` no es `programada`;
3. `MEDICO_INACTIVO` si `medico.activo` no es verdadero;
4. `ESPECIALIDAD_DISTINTA` si las especialidades no coinciden;
5. `MEDICO_AUSENTE` si alguna ausencia choca con la franja de la cita;
6. `MEDICO_OCUPADO` si alguna entrada de la agenda choca con la franja.

Dos franjas chocan si `a.inicio < b.fin` y `b.inicio < a.fin` (franjas contiguas no chocan). `agenda` y `ausencias` pueden faltar: cuentan como listas vacías.

### Solución
```javascript
function validar_reasignacion(entrada) {
  const { cita, medico } = entrada || {};
  const choca = (a, b) => a.inicio < b.fin && b.inicio < a.fin;
  if (!cita || !medico || !(cita.inicio < cita.fin)) return { ok: false, error: "ENTRADA_INVALIDA" };
  if (cita.estado !== "programada") return { ok: false, error: "CITA_NO_PROGRAMADA" };
  if (medico.activo !== true) return { ok: false, error: "MEDICO_INACTIVO" };
  if (medico.especialidad !== cita.especialidad) return { ok: false, error: "ESPECIALIDAD_DISTINTA" };
  if ((entrada.ausencias || []).some((a) => choca(a, cita))) return { ok: false, error: "MEDICO_AUSENTE" };
  if ((entrada.agenda || []).some((a) => choca(a, cita))) return { ok: false, error: "MEDICO_OCUPADO" };
  return { ok: true };
}
```
```python
def validar_reasignacion(entrada):
    entrada = entrada or {}
    cita, medico = entrada.get("cita"), entrada.get("medico")
    def choca(a, b):
        return a["inicio"] < b["fin"] and b["inicio"] < a["fin"]
    if not cita or not medico or not (cita["inicio"] < cita["fin"]):
        return {"ok": False, "error": "ENTRADA_INVALIDA"}
    if cita.get("estado") != "programada":
        return {"ok": False, "error": "CITA_NO_PROGRAMADA"}
    if medico.get("activo") is not True:
        return {"ok": False, "error": "MEDICO_INACTIVO"}
    if medico.get("especialidad") != cita.get("especialidad"):
        return {"ok": False, "error": "ESPECIALIDAD_DISTINTA"}
    if any(choca(a, cita) for a in entrada.get("ausencias") or []):
        return {"ok": False, "error": "MEDICO_AUSENTE"}
    if any(choca(a, cita) for a in entrada.get("agenda") or []):
        return {"ok": False, "error": "MEDICO_OCUPADO"}
    return {"ok": True}
```

- Franjas contiguas no chocan: usa comparaciones estrictas.
- Trata `agenda` y `ausencias` ausentes como listas vacías.

### Modelo
- **(a) Interfaz:** TypeScript v2, el único con soporte de interfaces de la Ontology. Riesgo: si el equipo sólo domina Python, hay que planear la curva; si el soporte cambia, revisar la tabla.
- **(b) Modelo de lenguaje:** TypeScript v2 o Python, que tienen integración con modelos de lenguaje mediante endpoints proxy y alias de modelo. Riesgo: costo y latencia por llamada, y que la salida del modelo no es determinista (pruebas con conjunto fijo, P4-05).
- **(c) Webhook:** TypeScript v1 lo llama directamente; en TypeScript v2 o Python hay que publicar el webhook como función de webhook. Riesgo: efecto externo que no se deshace con la edición (P2-06): registrar resultado y reconciliar.
### Regla
El lenguaje y el runtime de una función se eligen por la fila de la tabla de soporte que su uso necesita, y cada soporte parcial, beta o dependiente de configuración se anota como riesgo del diseño.
### Rúbrica

- (a) elige TypeScript v2.
- (b) elige TypeScript v2 o Python y nombra un riesgo del modelo de lenguaje.
