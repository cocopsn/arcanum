# A2-07 · Live coding y comunicación

## Antes de leer: fusionar sin ordenar
type: prediccion
id: a2-07-pred-orden
rol: prediccion

Esta primera versión fusiona intervalos cerrados recorriéndolos en el orden en que llegan:

```python
def fusionar(intervalos):
    res = []
    for a, b in intervalos:
        if res and a <= res[-1][1]:
            res[-1][1] = max(res[-1][1], b)
        else:
            res.append([a, b])
    return res
```

¿Qué devuelve `fusionar([[5, 6], [1, 2], [2, 5]])`?

### Opciones
- [[1, 6]], la respuesta correcta
- [x] [[5, 6]]
- [[5, 6], [1, 5]]
- Lanza un error porque la entrada no está ordenada

### Justificación
El primer intervalo es [5, 6]. Para [1, 2], la condición 1 ≤ 6 es verdadera y se «fusiona» extendiendo el fin a máx(6, 2) =
6, pero el inicio se queda en 5. Lo mismo pasa con [2, 5]. Resultado: [[5, 6]], que pierde el tramo de 1 a 5. Sin ordenar por
inicio, la condición compara intervalos que no son vecinos. Es el error que se corrige a la vista en el libro.

## Fusionar intervalos
type: code
id: a2-07-code-fusionar
tiempo: 15

Fusiona intervalos cerrados [a, b] que se traslapan o se tocan ([1, 4] y [4, 5] se fusionan). La entrada puede venir
desordenada; la salida va ordenada por inicio. Antes de programar, di en voz alta tus supuestos y tu plan con su costo.

### Especificación
Ordena una copia por inicio. Recorre: si el inicio actual es menor o igual al fin del último intervalo de la salida, extiende
ese fin al máximo de los dos; si no, agrega el intervalo. O(n log n).

### Firma
```javascript
function fusionarIntervalos(intervalos) {
  // tu código
}
```
```python
def fusionar_intervalos(intervalos):
    # tu código
    pass
```

### Casos
```json
[
  { "input": [[]], "expected": [] },
  { "input": [[[1, 3]]], "expected": [[1, 3]] },
  { "input": [[[1, 3], [2, 6], [8, 10], [15, 18]]], "expected": [[1, 6], [8, 10], [15, 18]] },
  { "input": [[[1, 4], [4, 5]]], "expected": [[1, 5]] },
  { "input": [[[5, 6], [1, 2], [2, 5]]], "expected": [[1, 6]] },
  { "input": [[[1, 10], [2, 3], [4, 5]]], "expected": [[1, 10]] },
  { "input": [[[6, 7], [1, 2]]], "expected": [[1, 2], [6, 7]] }
]
```

### Solución
```javascript
function fusionarIntervalos(intervalos) {
  const orden = intervalos.map((x) => x.slice()).sort((x, y) => x[0] - y[0]);
  const res = [];
  for (const [a, b] of orden) {
    if (res.length && a <= res[res.length - 1][1]) res[res.length - 1][1] = Math.max(res[res.length - 1][1], b);
    else res.push([a, b]);
  }
  return res;
}
```
```python
def fusionar_intervalos(intervalos):
    res = []
    for a, b in sorted(intervalos, key=lambda x: x[0]):
        if res and a <= res[-1][1]:
            res[-1][1] = max(res[-1][1], b)
        else:
            res.append([a, b])
    return res
```

### Pistas
- El caso [[5, 6], [1, 2], [2, 5]] es el que delata la falta de orden.
- Copia los intervalos antes de extenderlos para no modificar la entrada.

## Paréntesis balanceados
type: code
id: a2-07-code-balanceado
tiempo: 8

Devuelve `true` si los paréntesis, corchetes y llaves de `s` están balanceados y bien anidados. Los demás caracteres se
ignoran. Problema corto: practica narrar los cinco tiempos en menos de ocho minutos.

### Especificación
Recorre con una pila. Un carácter de apertura se apila. Uno de cierre exige que la cima sea su pareja; si la pila está vacía o
no coincide, es falso. Al final la pila debe quedar vacía.

### Firma
```javascript
function balanceado(s) {
  // tu código
}
```
```python
def balanceado(s):
    # tu código
    pass
```

### Casos
```json
[
  { "input": [""], "expected": true },
  { "input": ["()[]{}"], "expected": true },
  { "input": ["(]"], "expected": false },
  { "input": ["([)]"], "expected": false },
  { "input": ["{[]}"], "expected": true },
  { "input": ["(("], "expected": false },
  { "input": ["())"], "expected": false },
  { "input": ["a(b)c"], "expected": true }
]
```

### Solución
```javascript
function balanceado(s) {
  const par = { ")": "(", "]": "[", "}": "{" };
  const pila = [];
  for (const ch of s) {
    if (ch === "(" || ch === "[" || ch === "{") pila.push(ch);
    else if (ch in par) {
      if (pila.pop() !== par[ch]) return false;
    }
  }
  return pila.length === 0;
}
```
```python
def balanceado(s):
    par = {")": "(", "]": "[", "}": "{"}
    pila = []
    for ch in s:
        if ch in "([{":
            pila.append(ch)
        elif ch in par:
            if not pila or pila.pop() != par[ch]:
                return False
    return not pila
```

### Pistas
- «())» falla al cerrar con la pila vacía; «((» falla al final.
- Narra el borde de la cadena vacía antes de programar.

## Un error frente al observador
type: multiple_choice
id: a2-07-mc-error
rol: recuperacion

Sin volver al libro: a mitad de la verificación descubres que tu solución falla con un caso que tú mismo propusiste. El
observador lo vio. ¿Qué haces?

### Opciones
- Lo corriges rápido sin comentarlo, para no llamar la atención sobre el error.
- Borras la función y la reescribes desde cero en silencio, para entregar algo limpio.
- [x] Lo nombras, muestras con el caso dónde falla, corriges la parte mínima y vuelves a verificar ese caso y uno nuevo.
- Sigues con el siguiente problema y dejas el error para el final si sobra tiempo.

### Justificación
El observador evalúa cómo razonas, y un error bien tratado es evidencia de que verificas. Corregirlo en silencio o reescribir
todo sin explicar le quita la información que necesita: qué estaba mal y si el plan sigue en pie. Dejarlo para el final
entrega algo que sabes que falla.

## La verificación en voz alta, por escrito
type: production
id: a2-07-prod-narracion

Escribe, como lo dirías, la verificación de tu fusión de intervalos sobre el caso [[1, 4], [4, 5], [7, 8]]: qué miras en cada
paso y qué concluyes.

### Modelo
«Ordeno por inicio; ya venían ordenados: [1, 4], [4, 5], [7, 8]. La salida empieza vacía, así que agrego [1, 4]. Sigue
[4, 5]: su inicio, 4, es menor o igual al fin del último, 4, así que extiendo el fin a máx(4, 5) = 5; la salida es [1, 5].
Sigue [7, 8]: 7 es mayor que 5, así que lo agrego. Resultado: [[1, 5], [7, 8]]. Coincide con lo esperado, y el caso cubre el
borde de intervalos que se tocan, que fue mi supuesto inicial.»

### Regla
Verificar en voz alta es recorrer el código escrito con un ejemplo concreto, diciendo en cada paso qué condición se evalúa y
con qué valores, y cerrar comparando contra lo esperado.

### Rúbrica
- Recorre el código real, no la idea general.
- Dice en cada paso la condición y los valores que compara.
- Termina comparando con lo esperado y nombra el borde que el caso cubre.

## Giro: los intervalos llegan en flujo
type: giro
id: a2-07-giro-flujo
rol: transferencia

Cambia una restricción: a mitad de la sesión, el observador dice que los intervalos llegan uno por uno y que después de cada
llegada hay que poder dar la unión actual. Explica en voz alta cómo cambias el plan, qué estructura usas y qué conservas de lo
que ya tenías.

### Rúbrica
- Anuncia el cambio de plan y por qué volver a ordenar todo en cada llegada cuesta O(n log n) por evento.
- Propone mantener los intervalos fusionados ordenados (lista ordenada con búsqueda binaria o árbol balanceado) e insertar fusionando sólo con los vecinos que se traslapan.
- Da el costo por llegada: O(log n + k) con k intervalos absorbidos, o lo que corresponda a la estructura elegida.
- Conserva los supuestos y los casos de prueba anteriores como regresión.
