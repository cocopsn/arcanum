## Ocho de ocho
type: prediccion
id: ocho-de-ocho
rol: prediccion
tiempo: 3

En un mes hubo 8 fallas de sello y todas tuvieron un pico de temperatura en la hora anterior. Hubo 120 episodios de pico en total. Antes de calcular nada más, predice qué proporción de los picos terminó en falla y qué puedes afirmar.

### Opciones
- [x] Menos del 7 %: el pico precede a todas las fallas, pero casi nunca termina en una; se puede decir «precede» y, con la tabla completa, «está asociado», no «causa».
- El 100 %: si todas las fallas tuvieron pico, todos los picos causan fallas.
- El 50 %: la mitad de los picos termina en falla.
- No se puede calcular sin un modelo de aprendizaje automático.
### Justificación
8 de 120 episodios terminaron en falla (6.7 %). «Todas las fallas tuvieron pico» mira sólo un lado de la tabla. Para hablar de causa hace falta descartar coincidencia y causa común (por ejemplo, la carga) y, de preferencia, una intervención controlada.

## La tabla de dos lados
type: code
id: tabla-dos-lados
tiempo: 18

Escribe `tabla_dos_lados(serie, umbral, fallas, ventana)`. `serie` es una lista ordenada por `t` de `{ t, valor }` (minutos). Un **episodio** es una racha máxima de puntos consecutivos con `valor > umbral`; su inicio es el `t` de su primer punto. `fallas` es una lista de tiempos. ### Solución
```javascript
function tabla_dos_lados(serie, umbral, fallas, ventana) {
  const inicios = [];
  let dentro = false;
  for (const p of serie) {
    const arriba = p.valor > umbral;
    if (arriba && !dentro) inicios.push(p.t);
    dentro = arriba;
  }
  const precede = (inicio, f) => inicio >= f - ventana && inicio < f;
  let fcp = 0;
  for (const f of fallas) if (inicios.some((i) => precede(i, f))) fcp += 1;
  let ecf = 0;
  for (const i of inicios) if (fallas.some((f) => precede(i, f))) ecf += 1;
  return {
    fallas_con_precursor: fcp,
    fallas_sin_precursor: fallas.length - fcp,
    episodios_con_falla: ecf,
    episodios_sin_falla: inicios.length - ecf,
  };
}
```
```python
def tabla_dos_lados(serie, umbral, fallas, ventana):
    inicios = []
    dentro = False
    for p in serie:
        arriba = p["valor"] > umbral
        if arriba and not dentro:
            inicios.append(p["t"])
        dentro = arriba
    def precede(inicio, f):
        return f - ventana <= inicio < f
    fcp = sum(1 for f in fallas if any(precede(i, f) for i in inicios))
    ecf = sum(1 for i in inicios if any(precede(i, f) for f in fallas))
    return {
        "fallas_con_precursor": fcp,
        "fallas_sin_precursor": len(fallas) - fcp,
        "episodios_con_falla": ecf,
        "episodios_sin_falla": len(inicios) - ecf,
    }
```
### Pistas
- Primero agrupa los puntos sobre el umbral en episodios y guarda el inicio de cada uno.
- Una falla puede tener varios episodios antes y un episodio puede preceder a varias fallas: cuenta cada lado por separado.
- La ventana incluye `f − ventana` y excluye `f`.

## Propiedad de serie o tipo sensor

### Opciones

## Una arista en el grafo del sistema
type: multiple_choice
id: arista-grafo
tiempo: 2

Alguien dibuja en un grafo de sistema la arista «temperatura → falla de sello» y la presenta como hallazgo del diagnóstico. ¿Cuál es la lectura correcta?

### Opciones
- [x] Es una hipótesis del modelo del sistema, útil para simular escenarios; necesita la tabla de dos lados, el descarte de causas comunes y, de preferencia, una intervención controlada para afirmarse como causa.
- Es un hallazgo, porque el grafo se construyó con datos de la plataforma.
- Es falsa, porque la temperatura nunca causa fallas.
- Es irrelevante, porque los grafos de sistema no se usan para decidir.
### Justificación
Un grafo de sistema representa cómo creemos que se relacionan las variables y permite simular cambios; cada arista es un supuesto que los datos deben poner a prueba. Que la herramienta lo dibuje no lo vuelve evidencia causal.

## Protocolo de afirmación causal
type: production
id: protocolo-causal
tiempo: 12

Para el caso sintético de las autoclaves (8 fallas, 120 episodios de pico, 7 de 8 fallas con carga mayor al 90 %), escribe la recomendación al jefe de mantenimiento con el verbo que corresponde a la evidencia, las historias rivales que consideraste, qué dato descarta o sostiene cada una y la intervención que propones para poder decir «causa».

### Modelo
- **Recomendación:** «El pico de temperatura **precede** a todas las fallas y **está asociado** con ellas, pero sólo el 6.7 % de los picos terminó en falla. La evidencia es **consistente con una causa común por carga** (7 de 8 fallas con carga > 90 %). Bajar el setpoint no está sustentado.»
- **Historias rivales:** directa (temperatura daña el sello), causa común (carga), invertida (fuga que el control compensa con temperatura), coincidencia (picos frecuentes).
- **Datos:** la proporción de picos con falla debilita la directa; la carga en 7 de 8 sostiene la común; el orden de presión y temperatura dentro de la ventana decide la invertida.
- **Intervención:** limitar la carga al 85 % en dos autoclaves durante dos semanas y comparar con la tercera, con el mismo criterio de falla y la misma ventana.
### Regla
Una afirmación causal usa el verbo de su evidencia (precede, asociado, consistente con mecanismo, causa), considera historias rivales con el dato que discrimina cada una y propone una intervención controlada antes de recomendar un cambio de operación.
### Rúbrica
- Usa el verbo correcto para el nivel de evidencia.
- Presenta la tabla de dos lados (incluidos los picos sin falla).
- Considera al menos tres historias rivales con su dato discriminante.
- Propone una intervención controlada concreta.
