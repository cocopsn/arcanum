## Código: los k más frecuentes
type: code
id: a2-08-code-frecuentes
tiempo: 25

Devuelve los k valores más frecuentes de `a`, de mayor a menor frecuencia; si dos empatan, primero el valor menor. Si hay
menos de k valores distintos, devuelve todos.

### Especificación
Cuenta frecuencias con un diccionario. Ordena los pares (valor, frecuencia) por frecuencia descendente y luego por valor
ascendente. Toma los primeros k valores.

### Firma
```javascript
function topFrecuentes(a, k) {
  // tu código
}
```
```python
def top_frecuentes(a, k):
    # tu código
    pass
```

### Casos
```json
[
  { "input": [[1, 1, 1, 2, 2, 3], 2], "expected": [1, 2] },
  { "input": [[4, 4, 5, 5, 6], 2], "expected": [4, 5] },
  { "input": [[7], 3], "expected": [7] },
  { "input": [[], 1], "expected": [] },
  { "input": [[3, 1, 2], 2], "expected": [1, 2] },
  { "input": [[2, 2, 1, 1, 3, 3, 3], 1], "expected": [3] },
  { "input": [[5, 5, 9, 9, 9, 5, 1], 2], "expected": [5, 9] }
]
```

### Solución
```javascript
function topFrecuentes(a, k) {
  const cuenta = new Map();
  for (const x of a) cuenta.set(x, (cuenta.get(x) || 0) + 1);
  return [...cuenta.entries()]
    .sort((p, q) => q[1] - p[1] || p[0] - q[0])
    .slice(0, k)
    .map((p) => p[0]);
}
```
```python
def top_frecuentes(a, k):
    cuenta = {}
    for x in a:
        cuenta[x] = cuenta.get(x, 0) + 1
    orden = sorted(cuenta.items(), key=lambda p: (-p[1], p[0]))
    return [v for v, _ in orden[:k]]
```

### Pistas
- Pregunta el desempate antes de programar: cambia el orden de la salida.
- Con n grande y k chico, un heap de tamaño k evita ordenar todo; aquí ordenar basta.

## SQL: total por categoría
type: sql
id: a2-08-sql-categorias
orden: si

Devuelve cada categoría con el total vendido, incluidas las que no tienen ventas (con 0), ordenadas por total descendente y,
si empatan, por nombre ascendente. Columnas: nombre, total.

### Esquema
```sql
CREATE TABLE categorias (id INTEGER PRIMARY KEY, nombre TEXT NOT NULL);
CREATE TABLE ventas (id INTEGER PRIMARY KEY, categoria_id INTEGER NOT NULL, monto INTEGER NOT NULL);
```

### Datos
```sql
INSERT INTO categorias (id, nombre) VALUES (1, 'bombas'), (2, 'filtros'), (3, 'valvulas');
INSERT INTO ventas (id, categoria_id, monto) VALUES (1, 1, 100), (2, 1, 50), (3, 2, 70), (4, 3, 70), (5, 3, 10);
```

### Fixtures
```sql
-- fixture: base
```
```sql
-- fixture: sin-ventas
INSERT INTO categorias (id, nombre) VALUES (4, 'sellos');
```
```sql
-- fixture: empate
INSERT INTO ventas (id, categoria_id, monto) VALUES (6, 2, 10);
```

### Solución
```sql
SELECT c.nombre, COALESCE(SUM(v.monto), 0) AS total
FROM categorias AS c
LEFT JOIN ventas AS v ON v.categoria_id = c.id
GROUP BY c.id, c.nombre
ORDER BY total DESC, c.nombre ASC
```

### Ingenua
```sql
SELECT c.nombre, SUM(v.monto) AS total
FROM categorias AS c
JOIN ventas AS v ON v.categoria_id = c.id
GROUP BY c.id, c.nombre
ORDER BY total DESC
```

## Debug: la mediana
type: code
id: a2-08-code-mediana
tiempo: 20

Esta función tiene un bug sembrado:

```python
def mediana(xs):
    return xs[len(xs) // 2]
```

Escribe la versión corregida: la mediana de una lista de números (sin modificarla), el promedio de los dos centrales si la
longitud es par, y `null` (None) si la lista está vacía. Los casos incluyen las reproducciones del bug.

### Especificación
Ordena una copia. Si la longitud es impar, devuelve el central; si es par, el promedio de los dos centrales. Lista vacía:
null.

### Firma
```javascript
function mediana(xs) {
  // tu código
}
```
```python
def mediana(xs):
    # tu código
    pass
```

### Casos
```json
[
  { "input": [[3, 1, 2]], "expected": 2 },
  { "input": [[4, 1, 3, 2]], "expected": 2.5 },
  { "input": [[]], "expected": null },
  { "input": [[5]], "expected": 5 },
  { "input": [[1, 1]], "expected": 1 },
  { "input": [[10, -2, 7, 3]], "expected": 5 },
  { "input": [[2, 2, 9]], "expected": 2 }
]
```

### Solución
```javascript
function mediana(xs) {
  if (xs.length === 0) return null;
  const s = xs.slice().sort((a, b) => a - b);
  const m = Math.floor(s.length / 2);
  return s.length % 2 ? s[m] : (s[m - 1] + s[m]) / 2;
}
```
```python
def mediana(xs):
    if not xs:
        return None
    s = sorted(xs)
    m = len(s) // 2
    return s[m] if len(s) % 2 else (s[m - 1] + s[m]) / 2
```

### Pistas
- Hay tres bugs en una línea: no ordena, no promedia con longitud par y falla con la lista vacía.
- La reproducción mínima de cada uno: [3, 1, 2], [4, 1, 3, 2] y [].

## Sets independientes
type: multiple_choice
id: a2-08-mc-independientes
rol: recuperacion

Sin volver al libro: ¿qué hace que los tres sets del simulacro cuenten como independientes?

### Opciones
- Que se hagan el mismo día, uno tras otro, para medir resistencia.
- [x] Que traigan problemas distintos, se hagan en días distintos y no se vean las soluciones de uno antes del siguiente.
- Que el mismo set se repita hasta bajar de 60 minutos.
- Que cada set lo califique una persona distinta, aunque los problemas se repitan.

### Justificación
La independencia protege la validez: si los problemas se repiten o se vieron sus soluciones, el segundo intento mide memoria y
no la capacidad de resolver algo nuevo. Repetir hasta bajar el tiempo es entrenamiento, no simulacro. Cambiar de evaluador no
arregla problemas repetidos, y hacer los tres el mismo día mide otra cosa.
