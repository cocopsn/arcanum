## «No repitas consultas»

tiempo: 2

Las instrucciones del agente dicen «no repitas consultas innecesarias». La herramienta de disponibilidad devuelve siempre `MEDICO_OCUPADO` por un dato malo en la agenda. No hay ningún tope en la máquina de estados. Predice qué pasa.

### Opciones
- [x] El agente puede repetir la misma consulta muchas veces: una instrucción al modelo no es un límite de ejecución; sólo un tope en la máquina de estados lo detiene.
- El agente se detiene a la segunda consulta, porque las instrucciones lo prohíben.

- El agente propone igual otro médico, porque entiende el problema.
### Justificación
Las instrucciones influyen en el modelo, pero no garantizan nada. Los límites (tope por herramienta, tope de repeticiones idénticas, tope de vueltas por estado) se escriben en la máquina de estados del agente, y al alcanzarlos el agente se detiene y avisa a una persona.

## Limitar las llamadas repetidas
type: code
id: limitar-llamadas
tiempo: 15

Escribe `limitar(llamadas, tope_por_herramienta, repeticion_max)`. `llamadas` es la lista ordenada de `{ herramienta, args }` (con `args` como cadena) que el modelo intenta. `tope_por_herramienta` es un objeto `herramienta → máximo de llamadas permitidas en la sesión` (si una herramienta no aparece, no tiene tope). `repeticion_max` es el máximo de llamadas idénticas (misma herramienta y mismos `args`) **consecutivas permitidas**. Para cada llamada decide, en este orden: `repeticion` si permitirla haría pasar de `repeticion_max` la racha de llamadas idénticas permitidas; `tope` si la herramienta ya alcanzó su máximo; `ok` en otro caso. Las llamadas bloqueadas no cuentan para los topes ni cambian la racha. Devuelve `{ decisiones, permitidas }`.

### Solución
```javascript
function limitar(llamadas, tope_por_herramienta, repeticion_max) {
  const usos = new Map();
  let ultima = null;
  let racha = 0;
  const decisiones = [];
  for (const c of llamadas) {
    const clave = c.herramienta + "\u0000" + c.args;
    const nuevaRacha = clave === ultima ? racha + 1 : 1;
    const tope = Object.prototype.hasOwnProperty.call(tope_por_herramienta, c.herramienta) ? tope_por_herramienta[c.herramienta] : Infinity;
    if (nuevaRacha > repeticion_max) decisiones.push("repeticion");
    else if ((usos.get(c.herramienta) || 0) >= tope) decisiones.push("tope");
    else {
      decisiones.push("ok");
      usos.set(c.herramienta, (usos.get(c.herramienta) || 0) + 1);
      ultima = clave;
      racha = nuevaRacha;
    }
  }
  return { decisiones, permitidas: decisiones.filter((d) => d === "ok").length };
}
```
```python
def limitar(llamadas, tope_por_herramienta, repeticion_max):
    usos = {}
    ultima = None
    racha = 0
    decisiones = []
    for c in llamadas:
        clave = (c["herramienta"], c["args"])
        nueva_racha = racha + 1 if clave == ultima else 1
        tope = tope_por_herramienta.get(c["herramienta"], float("inf"))
        if nueva_racha > repeticion_max:
            decisiones.append("repeticion")
        elif usos.get(c["herramienta"], 0) >= tope:
            decisiones.append("tope")
        else:
            decisiones.append("ok")
            usos[c["herramienta"]] = usos.get(c["herramienta"], 0) + 1
            ultima = clave
            racha = nueva_racha
    return {"decisiones": decisiones, "permitidas": sum(1 for d in decisiones if d == "ok")}
```
### Pistas
- La racha sólo cuenta llamadas idénticas y permitidas una tras otra.
- Una llamada bloqueada no cambia ni la racha ni los usos.
- Revisa la repetición antes que el tope.

## Herramientas por estado
type: multiple_choice
id: herramientas-por-estado
tiempo: 2

En la máquina de estados del agente de agenda, ¿cuándo puede llamar la acción que aplica una reasignación?

### Opciones
- [x] Sólo en el estado «aplicando», al que se llega desde «en_revision» con el evento de aprobación de una persona.
- En cualquier estado, si el modelo está seguro.
- En «consultando», para ahorrar un paso cuando la disponibilidad sale libre.
- Nunca: los agentes no pueden aplicar acciones.
### Justificación
Una máquina de estados explícita dice qué herramientas se permiten en cada estado. Restringir la acción al estado posterior a la revisión hace que la aprobación humana sea una condición verificable y no una sugerencia.

## Instrumentación y límites de tu agente
type: production
id: instrumentacion-limites
tiempo: 12

Para el agente sintético de pedidos urgentes de farmacia, escribe su máquina de estados (estados, eventos y herramientas permitidas en cada estado), qué registra en cada paso, sus tres límites de ejecución con valores concretos, qué hace al alcanzar un límite y los pasos con que reconstruirías una falla.

### Modelo
- **Estados:** esperando → consultando (lectura de stock, entregas, consumo) → proponiendo (crear propuesta) → en_revision → aplicando (crear pedido) → cerrada; más detenido_por_limite.
- **Registro por paso:** estado, decisión y su razón, herramienta con argumentos, resultado resumido, duración y límite aplicado.
- **Límites:** 20 lecturas por sesión; 2 llamadas idénticas consecutivas; 5 vueltas en «consultando» sin pasar a «proponiendo».
- **Al alcanzar un límite:** pasa a detenido_por_limite, no reintenta y avisa a la jefatura con el último estado y la causa probable.
- **Reconstrucción:** filtrar sesiones por versión y origen; ubicar el primer evento anómalo; examinar el estado y el contexto en ese punto; ver la respuesta de la herramienta; concluir causa y defecto de diseño, y corregir ambos.
### Regla
Un agente observable tiene una máquina de estados explícita con herramientas por estado, registra cada decisión y llamada con su resultado y duración, aplica límites de ejecución escritos en la máquina (no en las instrucciones) que lo detienen con aviso, y permite reconstruir una falla paso a paso desde el historial.
### Rúbrica
- Define estados, eventos y herramientas permitidas por estado.
- Lista lo que se registra en cada paso.
- Da tres límites con valores concretos.
- Describe qué hace al alcanzar un límite.
