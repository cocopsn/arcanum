## Antes de leer: el arreglo que salió de la clase
type: prediccion
id: prediccion-arreglo-expuesto
rol: prediccion
tiempo: 2

Un `ConjuntoOrdenado` guarda sus elementos en un arreglo ordenado y responde `contiene(x)` con búsqueda binaria. Su método `elementos()` devuelve el arreglo interno, sin copiar. Un cliente hace `c.elementos().push(2)` sobre el conjunto {1, 3, 5}. ¿Qué es lo más probable que pase después?

### Opciones
- [x] El arreglo interno queda `[1, 3, 5, 2]`, fuera de orden; ninguna operación falla en ese momento, pero `contiene(2)` puede responder `false` y el error aparece lejos de su causa.
- El lenguaje impide el `push` porque el arreglo pertenece a la clase.
- El conjunto pasa a ser {1, 2, 3, 5} y todo sigue funcionando, porque `push` agrega elementos igual que `agregar`.
- La siguiente llamada a `contiene` lanza una excepción que señala la línea del `push`.
### Justificación
Devolver la representación es la primera puerta de la exposición: el cliente tiene una referencia al mismo arreglo y puede modificarlo sin pasar por ninguna operación pública. El invariante (orden estricto) se rompe en silencio. La búsqueda binaria no lanza nada: sólo responde mal, porque su corrección dependía del orden. En la mayoría de los lenguajes nada impide el `push`, y nada vuelve a ordenar el arreglo: `push` no es `agregar`.

## Función de abstracción o invariante
type: multiple_choice
id: af-o-ri-fraccion
tiempo: 3

Una `Fraccion` inmutable guarda dos enteros, `num` y `den`. Las operaciones suponen que la fracción está en forma reducida. ¿Qué par es una función de abstracción y un invariante de representación correctos para este diseño?

### Opciones
- [x] RI: `den > 0` y `mcd(|num|, den) = 1`. AF: la fracción representa el número racional `num / den`.
- RI: la fracción representa el número racional `num / den`. AF: `den > 0` y `mcd(|num|, den) = 1`.
- RI: `den ≠ 0`. AF: el par `(num, den)`.
- RI: `num` y `den` son enteros. AF: `num / den` redondeado a dos decimales.
### Justificación
El invariante es un predicado sobre la representación: dice qué pares son legales. Exigir `den > 0` y la forma reducida hace que cada racional tenga una sola representación, que es lo que las operaciones suponen. La función de abstracción lleva cada par legal al valor abstracto, el racional `num / den`. La segunda opción invierte los papeles. Con `den ≠ 0` como único RI se aceptan `(2, 4)` y `(-1, -2)`, que las operaciones no esperan, y «el par» no es un valor abstracto sino la propia representación. Redondear cambia el significado: dos racionales distintos acabarían representando lo mismo.

Encuentra argumentos `[datos, x]` que respeten el contrato y en los que la casi correcta devuelva algo distinto de la referencia.

### Firma
```javascript
function agregar(datos, x) {
  // datos: enteros en orden estrictamente creciente; x: entero
}
```

### Precondición
```javascript
function pre(datos, x) {
  if (!Array.isArray(datos) || datos.length > 100 || !Number.isInteger(x)) return false;
  for (let i = 0; i < datos.length; i++) {
    if (!Number.isInteger(datos[i])) return false;
    if (i > 0 && !(datos[i - 1] < datos[i])) return false;
  }
  return true;
}
```

### Casi correcta
```javascript
function agregar(datos, x) {
  let i = 0;
  while (i < datos.length && datos[i] < x) i++;
  if (i > 0 && datos[i - 1] === x) return datos.slice();
  const copia = datos.slice();
  copia.splice(i, 0, x);
  return copia;
}
```

## La función de abstracción de un deque circular
type: code
id: codigo-abstraer-deque
tiempo: 15

Un deque sobre arreglo circular se representa con `{ datos, frente, tam }`. Implementa su función de abstracción, protegida por su invariante: si la representación es legal, devuelve la secuencia abstracta; si no lo es, devuelve `null`.

### Especificación
`abstraer(rep)`:
- `rep` es un objeto con `datos` (arreglo), `frente` y `tam`.
- **RI:** `frente` y `tam` son enteros; `0 ≤ tam ≤ datos.length`; si `datos.length > 0`, entonces `0 ≤ frente < datos.length`; si `datos.length === 0`, entonces `frente === 0`.
- **AF:** la secuencia `datos[(frente + i) % datos.length]` para `i = 0 … tam − 1`, en ese orden. Con `tam = 0` es la secuencia vacía.
- Si el RI no se cumple, devuelve `null` (la AF no está definida).
- No modifiques `rep`.

### Firma
```javascript
function abstraer(rep) {
  // TODO: primero el RI; después lee tam elementos desde frente, dando la vuelta
  return [];
}
```
```python
def abstraer(rep):
    # TODO: primero el RI; después lee tam elementos desde frente, dando la vuelta
    return []
```

### Solución
```javascript
function abstraer(rep) {
  const { datos, frente, tam } = rep;
  if (!Array.isArray(datos) || !Number.isInteger(frente) || !Number.isInteger(tam)) return null;
  const cap = datos.length;
  if (tam < 0 || tam > cap) return null;
  if (cap === 0 ? frente !== 0 : frente < 0 || frente >= cap) return null;
  const out = [];
  for (let i = 0; i < tam; i++) out.push(datos[(frente + i) % cap]);
  return out;
}
```
```python
def abstraer(rep):
    datos = rep.get("datos")
    frente = rep.get("frente")
    tam = rep.get("tam")
    def entero(v):
        return isinstance(v, int) and not isinstance(v, bool)
    if not isinstance(datos, list) or not entero(frente) or not entero(tam):
        return None
    cap = len(datos)
    if tam < 0 or tam > cap:
        return None
    if cap == 0:
        if frente != 0:
            return None
    elif frente < 0 or frente >= cap:
        return None
    return [datos[(frente + i) % cap] for i in range(tam)]
```

### Pistas
- Comprueba el RI completo antes de leer un solo elemento: fuera del RI la AF no está definida.
- El caso `datos.length === 0` es especial: no hay índice válido, así que el RI fija `frente === 0`.
- Dar la vuelta es `(frente + i) % capacidad`, con la capacidad del arreglo, no con `tam`.

## Cerrar la puerta de entrada
type: multiple_choice
id: exposicion-constructor
tiempo: 3

El constructor de `ConjuntoOrdenado(lista)` ordena `lista` en su lugar, quita repetidos y la guarda en `this.datos`. Las pruebas pasan. ¿Cuál es el problema y cuál la corrección mínima?

### Opciones
- [x] El que llamó conserva la referencia a `lista` y puede modificarla después, rompiendo el invariante desde fuera; además el constructor alteró un arreglo ajeno. La corrección mínima es copiar antes de ordenar y guardar sólo la copia.
- No hay problema: ordenar en su lugar es más eficiente y el invariante se cumple al terminar el constructor.
- El problema es de rendimiento: ordenar cuesta O(n log n) y debería exigirse que `lista` llegue ordenada.
- La corrección es declarar `datos` como privado; con eso ya no se puede modificar desde fuera.
### Justificación
Guardar lo que te dieron es la segunda puerta de la exposición: el invariante vale al salir del constructor, pero el cliente comparte el arreglo y puede romperlo en cualquier momento sin tocar ninguna operación pública. Ordenar en su lugar además cambia un objeto que no es tuyo, un efecto que el contrato no declara. La copia defensiva cierra las dos cosas. Hacer privado el campo no sirve: el cliente no necesita el campo, ya tiene la referencia al mismo arreglo. Exigir la lista ordenada cambia la precondición y no resuelve el alias.

## Escribe la AF y el RI de un conjunto de intervalos
type: production
id: produccion-af-ri-intervalos
tiempo: 12

Un tipo `ConjuntoDeIntervalos` representa un conjunto de minutos del día como una lista de intervalos semiabiertos `[a, b)`. Escribe su invariante de representación y su función de abstracción, y argumenta en pocas líneas que la operación `agregar([a, b))`, que fusiona con los vecinos que traslapan o se tocan, preserva el invariante.

### Modelo
*Representación:* `bloques`, una lista de pares `[a, b]`.
*RI:* cada par cumple `0 ≤ a < b ≤ 1440` con enteros; la lista está ordenada por `a`; y para pares consecutivos `b_i < a_{i+1}` (estrictamente: dos bloques que se tocan deben estar fusionados, así cada conjunto tiene una sola representación).
*AF:* el conjunto de minutos `⋃ [a_i, b_i)`.
*Preservación en `agregar([a, b))`:* se localizan los bloques que traslapan o tocan `[a, b)`; se reemplazan por un solo bloque `[min(a, a_primero), max(b, b_último))`. Los bloques anteriores terminan antes de `a` y los posteriores empiezan después de `b`, sin tocarlo, así que el orden y la separación estricta se mantienen en las dos uniones nuevas; en el resto no cambió nada. La AF del resultado es la unión anterior más `[a, b)`, que es la especificación.

### Regla
El invariante es un predicado sobre la representación que define qué valores concretos son legales; la función de abstracción sólo está definida sobre ellos. Elegir un RI que dé una representación única por valor simplifica la igualdad y las operaciones.

### Rúbrica
- El RI es un predicado sobre la lista concreta, no una descripción del valor abstracto.
- El RI exige separación estricta entre bloques consecutivos o, si permite bloques que se tocan, lo declara y lo justifica.
- La AF lleva cada lista legal a un conjunto de minutos.
- El argumento de preservación revisa las dos uniones nuevas y dice por qué el resto no cambia.
- La AF del resultado coincide con la especificación de `agregar`.
