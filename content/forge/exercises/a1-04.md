Banco ligero de la ruta A1. La misión: implementar un BST, derivar la cota de altura de un AVL y explicar cuándo un árbol

## Antes de leer: claves que llegan ordenadas
type: prediccion
id: a1-04-pred-degenerado
rol: prediccion

Insertas las claves 1, 2, 3, …, 1,000, en ese orden, en un BST sin ningún balanceo. Después buscas la clave 1,000. ¿Cuántos
nodos visita la búsqueda?

### Opciones
- Unos 10, porque log₂ 1,000 ≈ 10
- Unos 500, la mitad en promedio
- [x] 1,000: el árbol quedó como una lista
- Unos 32, la raíz cuadrada

### Justificación
Cada clave nueva es mayor que todas las anteriores, así que se cuelga a la derecha de la última: el árbol es un camino de
1,000 nodos y altura 999. La búsqueda de la última clave los visita todos. El log₂ n sólo vale si algo mantiene la altura
baja, y aquí nada lo hace.

## Altura de un BST, desvanecido
type: desvanecido
id: a1-04-desv-altura
lang: javascript

Completa `alturaBST(claves)`: inserta las claves en orden en un BST simple (sin repetidos; un repetido se ignora) y devuelve
su altura, con un nodo solo = 0 y árbol vacío = −1.

### Pasos
1. Si el árbol está vacío, la clave pasa a ser la raíz.
2. Baja desde la raíz: a la izquierda si la clave es menor, a la derecha si es mayor; un repetido se ignora.
3. Cuelga el nodo nuevo en el hueco donde terminó el descenso.
4. Calcula la altura: −1 para vacío y 1 + el máximo de los hijos para los demás.
5. Con claves crecientes, cada clave nueva es mayor que todas las anteriores y baja siempre por la derecha: el árbol es un camino de n nodos, de altura n − 1, y buscar cuesta O(n).

### Plantilla
```javascript
function alturaBST(claves) {
  let raiz = null;
  for (const k of claves) {
    const nuevo = { k: k, izq: null, der: null };
    // <paso 1>
    if (raiz === null) { raiz = nuevo; continue; }
    // </paso 1>
    let p = raiz;
    while (true) {
      // <paso 2>
      if (k === p.k) break;
      const lado = k < p.k ? "izq" : "der";
      // </paso 2>
      // <paso 3>
      if (p[lado] === null) { p[lado] = nuevo; break; }
      p = p[lado];
      // </paso 3>
    }
  }
  // <paso 4>
  const h = (n) => (n === null ? -1 : 1 + Math.max(h(n.izq), h(n.der)));
  return h(raiz);
  // </paso 4>
}
```

## ¿Es un BST de verdad?

### Casos
```json
[
  { "input": [null], "expected": true },
  { "input": [[5, null, null]], "expected": true },
  { "input": [[5, [3, null, null], [8, null, null]]], "expected": true },
  { "input": [[5, [3, null, [6, null, null]], [8, null, null]]], "expected": false },
  { "input": [[5, [5, null, null], null]], "expected": false },
  { "input": [[10, [5, [2, null, null], [7, null, null]], [15, [12, null, null], [20, null, null]]]], "expected": true },
  { "input": [[10, [5, null, null], [15, [9, null, null], null]]], "expected": false }
]
```

### Solución
```javascript
function esBST(t) {
  function ok(n, lo, hi) {
    if (n === null) return true;
    const v = n[0];
    if (lo !== null && v <= lo) return false;
    if (hi !== null && v >= hi) return false;
    return ok(n[1], lo, v) && ok(n[2], v, hi);
  }
  return ok(t, null, null);
}
```
```python
def es_bst(t):
    def ok(n, lo, hi):
        if n is None:
            return True
        v, izq, der = n
        if lo is not None and v <= lo:
            return False
        if hi is not None and v >= hi:
            return False
        return ok(izq, lo, v) and ok(der, v, hi)
    return ok(t, None, None)
```

### Pistas
- Comparar sólo con el padre no alcanza: el 6 del cuarto caso es mayor que su padre 3 y aun así está a la izquierda de 5.
- El intervalo se estrecha al bajar; nunca se ensancha.

## Índices en disco
type: multiple_choice
id: a1-04-mc-disco
rol: recuperacion

Sin volver al libro: ¿por qué los índices de una base de datos en disco usan árboles B+ con nodos anchos y no un AVL binario?

### Opciones
- Porque un AVL no puede guardar claves repetidas.
- [x] Porque lo caro es leer páginas: con cientos de claves por nodo, la altura en páginas es muy baja y una búsqueda lee pocas.
- Porque un árbol B+ hace menos comparaciones en total que un AVL.
- Porque un AVL no admite consultas por rango.

### Justificación
En disco el costo dominante es cada lectura de página. Un nodo ancho del tamaño de una página reparte el árbol en pocos
niveles, así que una búsqueda lee pocas páginas. Hace incluso más comparaciones dentro de cada nodo, pero son baratas en
memoria. Un AVL sí admite repetidos con una regla de desempate y sí responde rangos recorriendo en orden; su problema es la
altura en lecturas de página.

## La cota del AVL, por escrito
type: production
id: a1-04-prod-cota-avl

Deriva, en seis a ocho líneas, que un AVL con n nodos tiene altura O(log n). Define N(h) y usa una desigualdad simple.

### Modelo
Sea N(h) el mínimo de nodos de un AVL de altura h, con N(−1) = 0 y N(0) = 1. El más flaco de altura h tiene una raíz, un
subárbol de altura h − 1 y otro de altura h − 2 (la diferencia máxima que permite el AVL), cada uno también mínimo: N(h) =
1 + N(h − 1) + N(h − 2). Como N crece con h, N(h) > 2 · N(h − 2). Repitiendo h/2 veces, N(h) > 2^(h/2). Si el árbol tiene
n nodos, n ≥ N(h) > 2^(h/2), así que h < 2 log₂ n = O(log n).

### Regla
Para acotar la altura de un árbol balanceado se cuenta el árbol válido con menos nodos para cada altura; la recurrencia de
ese mínimo da la cota.

### Rúbrica
- Define N(h) como el mínimo de nodos para la altura h, con casos base.
- Justifica la recurrencia con la regla de balance del AVL.
- Obtiene una cota exponencial de N(h) y la invierte para acotar h.

## Altura máxima con siete claves
type: multiple_choice
id: a1-04-mc-altura-avl

Con la convención de este banco (un nodo solo tiene altura 0), ¿cuál es la mayor altura posible de un AVL con 7 nodos?

### Opciones
- 2, porque 7 nodos llenan un árbol perfecto
- [x] 3, porque el AVL más flaco de altura 3 tiene exactamente N(3) = 7 nodos
- 4, porque N(4) = 12 es mayor que 7
- 6, como un BST degenerado

### Justificación
N(h) es el mínimo de nodos de un AVL de altura h: N(0) = 1, N(1) = 2, N(2) = 4, N(3) = 7, N(4) = 12. Con 7 nodos se puede
llegar a altura 3 (el árbol mínimo de esa altura), pero no a 4, que exige al menos 12. Altura 2 es la mínima posible, no la
máxima, y 6 sólo la alcanza un BST sin balanceo.
