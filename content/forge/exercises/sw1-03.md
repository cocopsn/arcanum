## Antes de leer: la propiedad que todo lo deja pasar
type: prediccion
id: prediccion-propiedad-debil
rol: prediccion
tiempo: 2

Un equipo prueba `ordenar(xs)` sobre 10,000 listas generadas con una sola propiedad: «la salida está en orden no decreciente». Todas pasan. ¿Cuál de estas implementaciones incorrectas también habría pasado esa prueba?

### Opciones
- [x] `return []`, porque una lista vacía está trivialmente ordenada.
- Ninguna: 10,000 listas generadas bastan para descartar cualquier implementación incorrecta.
- Sólo una que ordene de mayor a menor.
- Sólo una que lance una excepción con listas de más de 100 elementos.
### Justificación
La propiedad «está ordenada» restringe la forma de la salida pero no su relación con la entrada. `return []` la cumple siempre, igual que devolver `[1, 2, 3]` para cualquier entrada. Falta la propiedad de permutación (mismos elementos con las mismas multiplicidades), o la comparación contra una referencia. La cantidad de casos no compensa una propiedad débil: diez mil intentos de una prueba que no puede fallar siguen sin poder fallar. Ordenar de mayor a menor sí la viola, y una excepción haría fallar la prueba.

## La referencia obvia de una caché LRU

Escribe la referencia contra la que se compara una caché LRU rápida: una implementación lenta y obvia que procesa una secuencia de operaciones y devuelve lo que responde cada `get`.

### Especificación
`modeloLRU(capacidad, operaciones)`:
- `capacidad` es un entero ≥ 1.
- `operaciones` es una lista de `["put", llave, valor]` o `["get", llave]`; las llaves son cadenas y los valores enteros.
- Devuelve la lista de resultados de los `get`, en orden: el valor guardado o `null` si la llave no está.
- `get` de una llave presente la vuelve la más reciente.
- `put` de una llave presente actualiza su valor **y** la vuelve la más reciente.
- `put` de una llave nueva la agrega como la más reciente; si el número de llaves supera `capacidad`, se expulsa la menos reciente.
- Usa la representación más simple que puedas defender (por ejemplo, una lista de pares de menos a más reciente).

### Solución
```javascript
function modeloLRU(capacidad, operaciones) {
  const pares = [];
  const salida = [];
  for (const op of operaciones) {
    const i = pares.findIndex((p) => p[0] === op[1]);
    if (op[0] === "get") {
      if (i === -1) {
        salida.push(null);
        continue;
      }
      const [par] = pares.splice(i, 1);
      pares.push(par);
      salida.push(par[1]);
    } else {
      if (i !== -1) pares.splice(i, 1);
      pares.push([op[1], op[2]]);
      if (pares.length > capacidad) pares.shift();
    }
  }
  return salida;
}
```
```python
def modelo_lru(capacidad, operaciones):
    pares = []
    salida = []
    for op in operaciones:
        i = next((j for j, p in enumerate(pares) if p[0] == op[1]), -1)
        if op[0] == "get":
            if i == -1:
                salida.append(None)
                continue
            par = pares.pop(i)
            pares.append(par)
            salida.append(par[1])
        else:
            if i != -1:
                pares.pop(i)
            pares.append([op[1], op[2]])
            if len(pares) > capacidad:
                pares.pop(0)
    return salida
```

### Pistas
- Mantén la lista de menos a más reciente: la que se expulsa es siempre la primera.
- Un `put` sobre una llave que ya existe también cuenta como uso: quítala de su lugar y ponla al final.
- No optimices: esta función es el oráculo, y su valor está en que se vea correcta a simple vista.

## Reducir la secuencia que falla
type: trace
id: traza-reduccion
tiempo: 5

Una caché LRU de capacidad 2 tiene un error: al hacer `put` sobre una llave existente actualiza el valor pero no la vuelve la más reciente. La secuencia `put(a,1), put(b,2), get(b), put(a,7), put(c,3), get(a)` falla: la referencia responde `[2, 7]` y la implementación `[2, null]`. Aplicas la reducción simple: intentas quitar cada operación de izquierda a derecha, te quedas con la secuencia más corta si sigue fallando y vuelves a empezar, hasta que ninguna se pueda quitar. ¿Qué secuencia queda?

### Opciones
- [x] `put(a,1), put(b,2), put(a,7), put(c,3), get(a)`: quitar `get(b)` mantiene la falla porque `b` ya era la más reciente; después ninguna otra operación se puede quitar sin que la falla desaparezca.
- `put(a,7), put(c,3), get(a)`: las dos primeras operaciones sólo llenan la caché y siempre se pueden quitar.
- `put(b,2), put(a,7), put(c,3), get(a)`: el valor inicial de `a` no importa porque se sobrescribe.
- La secuencia original completa: cada operación participa en la falla.
### Justificación
Quitar `put(a,1)` convierte `put(a,7)` en la inserción de una llave nueva, que la implementación maneja bien, y la falla desaparece; quitar `put(b,2)` deja la caché sin llenarse y nadie es expulsado. Quitar `get(b)` no cambia la recencia (`b` ya era la más reciente), y la falla sigue: es la primera reducción aceptada. Sobre la secuencia de cinco operaciones, quitar cualquiera hace desaparecer la falla: sin la actualización no hay error, sin `put(c,3)` no hay expulsión y sin `get(a)` no hay nada observable. Por eso el resultado es mínimo respecto a quitar una operación.

## Elegir la referencia
type: multiple_choice
id: elegir-referencia
tiempo: 3

Vas a probar un árbol AVL nuevo con secuencias generadas de `insertar`, `borrar` y `contiene`. ¿Qué usarías como referencia?

### Opciones
- [x] Un arreglo ordenado con búsqueda lineal, escrito sin reutilizar nada del AVL: es lento, pero cada operación se ve correcta a simple vista y no comparte ningún error con el árbol.
- Otro AVL del mismo equipo que reutiliza la función de rotación, porque así la comparación es más rápida.
- El mismo AVL con aserciones internas activadas: si no lanza, coincide consigo mismo.
- Ninguna referencia: basta con comprobar que el árbol sigue balanceado después de cada operación.
### Justificación
Una referencia sirve si es obviamente correcta y no comparte código con lo que se prueba. El arreglo ordenado implementa directamente la función de abstracción del conjunto; su lentitud no importa con secuencias de cientos de operaciones. Reutilizar la rotación hace que las dos implementaciones coincidan justo en el error más probable. Comparar el árbol consigo mismo no puede fallar por diferencias. El balance es un invariante útil, pero no dice si `contiene` responde bien: un árbol perfectamente balanceado puede haber perdido un elemento.

## Propiedades para fusionar intervalos
type: production
id: produccion-propiedades-fusion
tiempo: 12

Para `fusionarIntervalos(intervalos)` (fusiona los intervalos que se traslapan o se tocan y devuelve la lista consolidada ordenada por inicio), escribe tres propiedades que juntas rechacen `return []` y rechacen devolver la entrada sin fusionar, describe una referencia obvia y nombra un error que tus propiedades todavía podrían dejar pasar.

### Modelo
*Propiedades:* (1) **cobertura exacta**: un punto entero está cubierto por la salida si y sólo si está cubierto por algún intervalo de la entrada; rechaza `return []` y cualquier pérdida o invención de rango. (2) **separación**: en la salida, para intervalos consecutivos, el fin de uno es estrictamente menor que el inicio del siguiente; rechaza devolver la entrada sin fusionar cuando hay traslapes o contactos. (3) **orden**: la salida está ordenada por inicio. Juntas determinan la salida de forma única.
*Referencia:* marcar en un arreglo de booleanos cada punto cubierto en el rango de la entrada y reconstruir los intervalos recorriéndolo; sólo sirve para valores pequeños, que es lo que usa el generador.
*Error que puede escapar:* con el generador limitado a valores entre 0 y 50, no se ejercita un desbordamiento o una pérdida de precisión con valores enormes; tampoco se prueba que la función no modifique su entrada si ninguna propiedad lo revisa.

### Regla
Una propiedad vale por lo que rechaza. Varias propiedades juntas, o una referencia obvia, deben restringir la salida lo suficiente para que sólo una implementación correcta las cumpla; y todo generador tiene un límite que hay que declarar.

### Rúbrica
- Al menos una propiedad relaciona la salida con la entrada (cobertura o equivalencia), de modo que `return []` falla.
- Al menos una propiedad rechaza devolver la entrada sin fusionar.
- La referencia no comparte código con la implementación probada y se ve correcta a simple vista.
- Nombra un error concreto que el generador o las propiedades no pueden encontrar.
- Las propiedades se pueden comprobar automáticamente, sin juicio humano.
