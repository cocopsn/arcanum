## El folio de facturación
type: prediccion
id: folio-facturacion
rol: prediccion
tiempo: 2

En el conjunto de prueba, los 30 mensajes de facturación traen un folio con formato fijo `FAC-` seguido de dígitos. Comparas una regla («si trae un folio FAC-, es facturación») con un clasificador basado en un LLM. Predice cuál acierta más en ese segmento y qué conviene hacer.

### Opciones
- [x] La regla acierta los 30 sin costo por llamada; el LLM, a lo sumo, empata: en ese segmento la IA no tiene nada que mejorar y la regla se queda.
- El LLM acierta más, porque entiende el contexto del mensaje.
- Los dos fallan, porque el folio no indica la intención.
- No se puede saber sin entrenar un modelo predictivo.
### Justificación
Cuando la señal es explícita y estable, una regla es exacta, auditable y gratis. El LLM puede igualarla, pero no superarla en ese segmento, y agrega costo, latencia y una forma nueva de equivocarse. La IA se reserva para lo que la regla deja sin resolver, y la decisión se sostiene midiendo ambos en el mismo conjunto.

### Solución
```javascript
function evaluar_regla(reglas, mensajes) {
  const norm = (s) => s.normalize("NFD").replace(/[\u0300-\u036f]/g, "").toLowerCase();
  const clasificar = (texto) => {
    const t = norm(texto);
    for (const r of reglas) if (r.patrones.some((p) => t.includes(norm(p)))) return r.clase;
    return "otro";
  };
  const errores = [];
  let aciertos = 0;
  for (const m of mensajes) {
    if (clasificar(m.texto) === m.etiqueta) aciertos += 1;
    else errores.push(m.id);
  }
  return { total: mensajes.length, aciertos, errores: errores.sort() };
}
```
```python
import unicodedata

def evaluar_regla(reglas, mensajes):
    def norm(s):
        return "".join(c for c in unicodedata.normalize("NFD", s) if not unicodedata.combining(c)).lower()
    def clasificar(texto):
        t = norm(texto)
        for r in reglas:
            if any(norm(p) in t for p in r["patrones"]):
                return r["clase"]
        return "otro"
    errores = []
    aciertos = 0
    for m in mensajes:
        if clasificar(m["texto"]) == m["etiqueta"]:
            aciertos += 1
        else:
            errores.append(m["id"])
    return {"total": len(mensajes), "aciertos": aciertos, "errores": sorted(errores)}
```
### Pistas
- Normaliza texto y patrones de la misma forma antes de comparar.
- La primera regla que aplica gana: el orden de la lista es parte de la regla.
- Los errores de la regla de base son la lista de casos donde un modelo podría aportar.

## La parte que no necesita IA
type: multiple_choice
id: parte-sin-ia
tiempo: 2

En el flujo de mensajes de pacientes, ¿qué parte **no** debe resolverla ningún modelo?

### Opciones
- [x] Ejecutar la cancelación: es una acción con condiciones exactas y efecto irreversible que se hace con criterios de envío y la confirmación del paciente.
- Clasificar mensajes ambiguos como «ya no voy a poder ir».
- Encontrar la respuesta aprobada más parecida a una duda administrativa.
- Extraer la fecha propuesta de un mensaje de reagendado.
### Justificación
Clasificar, buscar y extraer son tareas de lenguaje abierto donde un error es recuperable. Ejecutar una cancelación es aplicar una regla exacta sobre una decisión que ya tomó el paciente; un modelo sólo agregaría una forma de equivocarse sobre algo que no se deshace fácil.
