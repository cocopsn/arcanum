# A2-05 · Learning drill: reglas nuevas

Banco ligero de la ruta A2. La misión: aprender una DSL pequeña que se entrega al iniciar, extenderla con una regla nueva sin
romper las anteriores y hacer preguntas útiles.

**La DSL de inventario.** Cada línea son tokens separados por un espacio. `ALTA sku n` suma n unidades. `BAJA sku n` resta n
si el saldo alcanza; si no, rechaza la línea sin cambiar nada. `CONSULTA sku` agrega el saldo actual (0 si nunca hubo) a la
salida. n es un entero positivo escrito con dígitos. Cualquier otra línea, o un comando con argumentos inválidos, se rechaza.
El resultado es `[consultas, rechazos]`.

## Antes de leer: una baja sin saldo
type: prediccion
id: a2-05-pred-baja
rol: prediccion

La DSL de inventario: `ALTA sku n` suma n unidades; `BAJA sku n` resta n si el saldo alcanza y, si no, rechaza la línea sin
cambiar nada; `CONSULTA sku` agrega el saldo a la salida; cualquier otra línea se rechaza. El resultado es
`[consultas, rechazos]`. ¿Qué devuelve el programa `ALTA A 5`, `BAJA A 7`, `CONSULTA A`?

### Opciones
- [x] [[5], 1]: la baja se rechaza completa y el saldo sigue en 5
- [[0], 0]: la baja deja el saldo en 0 porque no puede bajar de ahí
- [[-2], 0]: la baja se aplica y el saldo queda negativo
- El programa se detiene en la baja y no hay salida

### Justificación
La especificación dice que una BAJA sin saldo suficiente se rechaza sin cambiar nada, así que A sigue con 5 y se cuenta un
rechazo. Bajar «lo que haya» o dejar saldos negativos son reglas razonables en otros sistemas, pero no son las de esta DSL, y
ninguna línea detiene el programa. Leer la especificación antes de suponer es la mitad del ejercicio.

## El intérprete base
type: code
id: a2-05-code-base

Implementa `ejecutar(lineas)` para la DSL de inventario: `ALTA sku n` suma n unidades; `BAJA sku n` resta n si el saldo
alcanza y, si no, rechaza la línea sin cambiar nada; `CONSULTA sku` agrega el saldo actual (0 si nunca hubo) a la salida;

rechazo.

```json
  { "input": [["ALTA A 5", "BAJA A 7", "CONSULTA A"]], "expected": [[5], 1] },

  { "input": [["VENDE A 1", "ALTA A", "ALTA A x", "CONSULTA"]], "expected": [[], 4] },

```

### Solución
```javascript
function ejecutar(lineas) {
  const stock = new Map();
  const consultas = [];
  let rechazos = 0;
  const de = (s) => stock.get(s) || 0;
  const esN = (x) => /^[0-9]+$/.test(x) && Number(x) > 0;
  for (const linea of lineas) {
    const t = linea.split(" ");
    if (t[0] === "ALTA" && t.length === 3 && esN(t[2])) stock.set(t[1], de(t[1]) + Number(t[2]));
    else if (t[0] === "BAJA" && t.length === 3 && esN(t[2])) {
      const n = Number(t[2]);
      if (de(t[1]) >= n) stock.set(t[1], de(t[1]) - n);
      else rechazos++;
    } else if (t[0] === "CONSULTA" && t.length === 2) consultas.push(de(t[1]));
    else rechazos++;
  }
  return [consultas, rechazos];
}
```
```python
import re

def ejecutar(lineas):
    stock = {}
    consultas = []
    rechazos = 0

    def es_n(x):
        return re.fullmatch(r"[0-9]+", x) is not None and int(x) > 0

    for linea in lineas:
        t = linea.split(" ")
        if t[0] == "ALTA" and len(t) == 3 and es_n(t[2]):
            stock[t[1]] = stock.get(t[1], 0) + int(t[2])
        elif t[0] == "BAJA" and len(t) == 3 and es_n(t[2]):
            n = int(t[2])
            if stock.get(t[1], 0) >= n:
                stock[t[1]] = stock.get(t[1], 0) - n
            else:
                rechazos += 1
        elif t[0] == "CONSULTA" and len(t) == 2:
            consultas.append(stock.get(t[1], 0))
        else:
            rechazos += 1
    return [consultas, rechazos]
```

## La regla nueva: TRASPASO
type: code
id: a2-05-code-traspaso
tiempo: 12

Extiende el intérprete de la DSL de inventario (ALTA suma, BAJA resta sólo si alcanza, CONSULTA agrega el saldo, todo lo
demás se rechaza): `TRASPASO a b n` mueve n unidades de a a b. Si a no alcanza, la línea se rechaza completa y nada cambia
(un solo rechazo). Las reglas anteriores tienen que seguir igual: los casos incluyen regresión.

### Especificación
Agrega un caso al despacho para TRASPASO con 4 tokens y n válido. Comprueba el saldo de a antes de tocar nada; si alcanza,
resta en a y suma en b. Si a y b son el mismo, el saldo no cambia. No implementes el traspaso como una BAJA seguida de una
ALTA independientes.

```javascript
  // tu código
}
```

```python
    # tu código
```

```javascript
function ejecutarConTraspaso(lineas) {
  const stock = new Map();
  const consultas = [];
  let rechazos = 0;
  const de = (s) => stock.get(s) || 0;
  const esN = (x) => /^[0-9]+$/.test(x) && Number(x) > 0;
  for (const linea of lineas) {
    const t = linea.split(" ");
    if (t[0] === "ALTA" && t.length === 3 && esN(t[2])) stock.set(t[1], de(t[1]) + Number(t[2]));
    else if (t[0] === "BAJA" && t.length === 3 && esN(t[2])) {
      const n = Number(t[2]);
      if (de(t[1]) >= n) stock.set(t[1], de(t[1]) - n);
      else rechazos++;
    } else if (t[0] === "CONSULTA" && t.length === 2) consultas.push(de(t[1]));
    else if (t[0] === "TRASPASO" && t.length === 4 && esN(t[3])) {
      const n = Number(t[3]);
      if (de(t[1]) >= n) {
        stock.set(t[1], de(t[1]) - n);
        stock.set(t[2], de(t[2]) + n);
      } else rechazos++;
    } else rechazos++;
  }
  return [consultas, rechazos];
}
```

## La pregunta útil
type: multiple_choice
id: a2-05-mc-pregunta
rol: recuperacion

Sin volver al libro: antes de implementar TRASPASO, ¿cuál de estas preguntas al entrevistador es la más útil?

### Opciones
- ¿Puedo usar un diccionario para los saldos?
- [x] Si el origen no alcanza, ¿se rechaza todo el traspaso o se mueve lo que haya?
- ¿Qué significa ALTA?
- ¿En qué lenguaje prefieren que lo escriba?

### Justificación
La especificación no dice qué pasa con un traspaso parcial, y la respuesta cambia el código: atómico o parcial, y cuántos
rechazos se cuentan. Preguntar por el diccionario o por el lenguaje no cambia el comportamiento, y lo que hace ALTA ya está
escrito en la especificación: preguntarlo muestra que no se leyó.

## Preguntas y regresión, por escrito
type: production
id: a2-05-prod-plan

Escribe, antes de programar TRASPASO, tres preguntas que harías y tu plan para no romper las reglas anteriores.

### Modelo
Preguntas: (1) si el origen no alcanza, ¿se rechaza todo o se mueve lo que haya?; (2) si origen y destino son el mismo, ¿es
válido y qué cambia?; (3) un traspaso rechazado, ¿cuenta como uno o dos rechazos? Plan: los programas que ya probé a mano
quedan como pruebas de regresión y los corro antes y después del cambio; TRASPASO entra como un caso nuevo del despacho sin
tocar ALTA, BAJA ni CONSULTA; compruebo el saldo del origen antes de modificar nada para que sea atómico, y agrego tres
pruebas nuevas: éxito, rechazo y origen igual a destino.

### Regla
Una regla nueva se aprende preguntando lo que la especificación no dice y se integra con las pruebas viejas como regresión;
sin esas dos cosas, extender es adivinar.

### Rúbrica
- Al menos dos preguntas cambian el comportamiento que vas a programar.
- Mantiene las pruebas anteriores como regresión y dice cuándo las corre.
- Diseña la regla como atómica y la prueba con éxito, rechazo y un borde.
