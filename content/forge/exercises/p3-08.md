### Solución
```javascript
function medir_tarea(sesiones) {
  const comp = sesiones.filter((s) => s.completada);
  const xs = comp.map((s) => s.segundos).sort((a, b) => a - b);
  let mediana = null;
  if (xs.length) {
    const m = Math.floor(xs.length / 2);
    mediana = xs.length % 2 ? xs[m] : (xs[m - 1] + xs[m]) / 2;
  }
  return {
    total: sesiones.length,
    completadas: comp.length,
    sin_ayuda: comp.filter((s) => !s.ayuda).length,
    mediana_segundos: mediana,
  };
}
```
```python
def medir_tarea(sesiones):
    comp = [s for s in sesiones if s["completada"]]
    xs = sorted(s["segundos"] for s in comp)
    mediana = None
    if xs:
        m = len(xs) // 2
        mediana = xs[m] if len(xs) % 2 else (xs[m - 1] + xs[m]) / 2
    return {
        "total": len(sesiones),
        "completadas": len(comp),
        "sin_ayuda": sum(1 for s in comp if not s["ayuda"]),
        "mediana_segundos": mediana,
    }
```
### Pistas
- La mediana se calcula sólo con las sesiones completadas.
- «Sin ayuda» cuenta completadas que no pidieron ayuda, no todas las sesiones sin ayuda.

## ¿Quién maneja la demo?

### Opciones

La usabilidad se observa cuando la persona hace la tarea sin quien construyó la aplicación. Un instructivo paso a paso mide la lectura del instructivo, no el flujo; y una demo propia, grabada o en vivo, sólo prueba que el autor sabe usarla.

## Lo que un handoff debe contestar
type: multiple_choice
id: handoff-contesta
tiempo: 2

¿Cuál de estos contenidos es imprescindible en el handoff de la aplicación de reasignaciones para que otra persona la mantenga sin llamarte?

### Opciones
- [x] Qué decisión sirve cada pantalla, qué objetos, acciones y funciones usa con sus criterios y dueños, dónde vive el módulo y quién lo abre, la medición vigente, errores conocidos y cómo se recupera.
- Una captura de cada pantalla con su título.
- La historia de cómo se te ocurrió la aplicación.
- Tu número de teléfono para dudas.
### Justificación
El handoff existe para que la aplicación funcione sin su autor. Las capturas ayudan, pero no dicen qué decisión sirve cada pantalla ni qué acción protege una regla. Dónde vive el módulo importa porque hereda los permisos de su proyecto o carpeta.

## Redacta el handoff
type: production
id: redactar-handoff
tiempo: 15

Redacta el handoff de una página de la aplicación de reasignaciones de la clínica ficticia, después de dos rondas de observación (ronda 1: 4 de 5 completaron, 2 sin ayuda, mediana 13:20; ronda 2: 5 de 5, 4 sin ayuda, mediana 8:50). Incluye las secciones que una persona nueva necesita y termina con cómo probarías que el handoff funciona.

### Modelo
- **Para qué sirve:** una pantalla, una decisión: «qué cita reasigno ahora y a quién», para la coordinación de cada sede.
- **Piezas:** objetos Cita, Medico, Reasignacion; acciones ReasignarCita y RevertirReasignacion con sus criterios de envío (misma especialidad, sin choque, cita no iniciada, sólo coordinación); función de disponibilidad (Python) con sus códigos de error; dueños de cada pieza.
- **Dónde vive y quién la abre:** carpeta del proyecto «Coordinación»; hereda sus permisos; la recepción no tiene acceso.
- **Medición vigente:** tarea «reasignar las citas de un médico ausente»; ronda 2: 5 de 5 completaron, 4 sin ayuda, mediana 8:50; criterio de éxito: 4 de 5 sin ayuda en menos de 10 minutos.
- **Errores conocidos:** el sugerido puede quedar viejo si se cambia la selección y se envía en el mismo gesto (mitigado con validación en la acción); no se probó con dos coordinadoras a la vez en la misma sede.
- **Recuperación:** revertir con la acción sobre el registro; apagar la automatización de recordatorios si envía de más.
- **Prueba del handoff:** otra persona agrega la columna «sede» y cambia un mensaje de rechazo siguiendo sólo este documento; se anota dónde se atoró y se corrige el documento.
### Regla
Un handoff permite mantener la aplicación sin su autor: dice qué decisión sirve, qué piezas la sostienen con sus reglas y dueños, dónde vive y quién la abre, cómo se mide y con qué resultado, qué falta probar y cómo se recupera; y se prueba con otra persona haciendo un cambio pequeño.
### Rúbrica
- Nombra la decisión y el usuario de la pantalla.
- Lista objetos, acciones y funciones con sus criterios y dueños.
- Dice dónde vive el módulo y quién lo puede abrir.
- Incluye la medición vigente con su criterio de éxito.
- Declara errores conocidos, lo no probado y la recuperación, y cómo se prueba el handoff.
