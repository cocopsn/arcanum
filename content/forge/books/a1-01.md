> ¿Cómo sabes que tu búsqueda binaria es correcta para todas las entradas, y no sólo para las cinco que probaste?

Este libro es ligero a propósito. La teoría completa de análisis asintótico vive en
[el libro de ITC C1](#libro:itc-c1); aquí sólo está lo propio de la misión de A1-01: **probar** la correctitud y el costo de
dos algoritmos pequeños, búsqueda binaria e insertion sort, y defender por qué el invariante elegido alcanza.

## La misión: una prueba tiene tres partes

Un invariante de lazo es una afirmación sobre el estado que es verdadera antes de cada vuelta. Para que sirva como prueba
tiene que pasar tres pruebas pequeñas, y las tres se escriben antes de confiar en el código:

1. **Inicio.** Es verdadera antes de la primera vuelta, con los valores iniciales de las variables.
2. **Mantenimiento.** Si es verdadera al empezar una vuelta, sigue siéndolo al empezar la siguiente.
3. **Salida.** Cuando el lazo termina, el invariante junto con la condición de salida implica lo que querías demostrar.

Falta una cuarta pieza, que suele olvidarse: **terminación**. Hay que nombrar una cantidad entera que baja en cada vuelta y
no puede bajar para siempre. En la búsqueda binaria esa cantidad es `hi - lo`; en insertion sort, el número de elementos
que faltan por insertar. Las notas de la unidad de algoritmos y cómputo de
[MIT 6.006](https://www.ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/pages/lecture-notes/) usan el mismo
esqueleto (correctitud por inducción y eficiencia contada en operaciones), y conviene leerlas junto con este libro.

## La cota: contar vueltas, no segundos

La cota de costo sale de la misma cantidad que prueba la terminación. En la búsqueda binaria sobre un intervalo de tamaño
`m`, cada vuelta deja un intervalo de tamaño a lo sumo `⌊m/2⌋`, así que tras `k` vueltas queda a lo sumo `n / 2^k` y el lazo
corre como mucho `⌊log₂ n⌋ + 1` veces. En insertion sort, cada desplazamiento corrige exactamente una **inversión** (un par
`i < j` con `a[i] > a[j]`), y cada inserción hace a lo sumo una comparación que no desplaza. Con `I` inversiones el trabajo
es `Θ(n + I)`: `I = 0` si la entrada ya viene ordenada e `I = n(n − 1)/2` si viene al revés. Las notas de ordenamiento de
[MIT 6.006](https://www.ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/pages/lecture-notes/) analizan
insertion sort contando sus operaciones. La práctica con conjuntos de problemas está en los
[assignments de MIT 6.006](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/pages/assignments/)
(selección de unidades; no equivale a haber completado el curso).

## Ejemplo trabajado

Queremos `primerMayorIgual(a, x)`: el primer índice `i` con `a[i] >= x` en un arreglo ordenado, o `n` si no existe.

```javascript
function primerMayorIgual(a, x) {
  let lo = 0, hi = a.length;           // intervalo semiabierto [lo, hi)
  while (lo < hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (a[mid] < x) lo = mid + 1;      // mid y todo lo anterior son < x
    else hi = mid;                     // mid es candidato; lo posterior sobra
  }
  return lo;
}
```

**Invariante.** Todo índice menor que `lo` cumple `a[i] < x`, y todo índice mayor o igual que `hi` cumple `a[i] >= x`.

- *Inicio:* `lo = 0` y `hi = n`; no hay índices menores que 0 ni mayores o iguales que `n`, así que se cumple sin esfuerzo.
- *Mantenimiento:* si `a[mid] < x`, por el orden todos los índices hasta `mid` son menores que `x` y mover `lo` a `mid + 1`
  conserva la primera mitad de la frase. Si `a[mid] >= x`, todo índice desde `mid` es mayor o igual, y `hi = mid` conserva la
  segunda.
- *Salida:* al terminar `lo == hi`; todo lo que está antes es menor que `x` y todo lo que está desde ahí es mayor o igual. Ese
  índice es, por definición, la respuesta.
- *Terminación:* `mid` cae en `[lo, hi)`, así que cada rama reduce `hi − lo` en al menos 1.

## Contraejemplo

Un invariante puede ser **verdadero y aun así inútil**. «Si `x` está en el arreglo, está en `[lo, hi]`» es cierto en la
versión que devuelve al encontrar `a[mid] === x`, pero no dice nada sobre *cuál* aparición devuelve. Con
`a = [1, 2, 2, 2, 3]` y `x = 2`, esa versión mira primero `mid = 2` y devuelve 2, mientras que la primera aparición está en
el índice 1. La salida no se sigue del invariante: faltaba la mitad de la frase que habla de lo que quedó a la izquierda.

## Diagrama

```text
 índice:     0   1   2   3   4            x = 2
 a:        [ 1 , 2 , 2 , 2 , 3 ]
 vuelta 1:  lo=0 hi=5 mid=2   a[2]=2 >= x  ->  hi=2
 vuelta 2:  lo=0 hi=2 mid=1   a[1]=2 >= x  ->  hi=1
 vuelta 3:  lo=0 hi=1 mid=0   a[0]=1 <  x  ->  lo=1
 salida:    lo = hi = 1

   [ 0 .. lo )  todos < x   |   [ hi .. n )  todos >= x
                  la frontera es la respuesta
```
